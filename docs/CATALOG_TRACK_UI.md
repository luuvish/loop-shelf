# 수록곡 검색 화면

2026-10-25. **저장한 카탈로그 → 수록곡 검색**에서 관리 중인 합성 곡 제목을 검색합니다. 외부 통합 앨범 검색, 개인 메모 검색과 구분하며 실제 수집·재생은 활성화하지 않습니다. [조회/페이지 계약](CATALOG_TRACK_SEARCH.md)을 따릅니다.

## 사용 흐름

- 곡 제목과 출처를 선택하고 **곡 검색**을 누릅니다. 입력/출처 변경 자체로 검색하지 않습니다. 한일문 1–2자·리터럴 기호를 지원하고 빈/제어 문자/정규화 후 200자 초과 입력은 거절합니다.
- 현재 곡 제목·앨범·소스·현재 위치·반복 표시 번호·길이와 합성 상태를 표시합니다. null 길이는 미확인, 0은 0:00입니다. 같은 이름도 별도 UUID 행으로 유지합니다. 자료 근거에서 앨범 제목/곡 목록의 취득 시각과 보관 기한을 따로 볼 수 있습니다.
- **이전/다음**은 메모리에 보관한 요청 커서만 사용해 서버에서 다시 읽습니다. 이전 페이지의 결과 본문을 재사용하거나 누적하지 않습니다. 첫 페이지를 제외한 요청에는 cursor를 사용하며 offset은 보내지 않습니다. 표시 페이지 번호는 이번 이동 경로이며 전체 건수/고정된 전체 페이지 수가 아닙니다.
- 기준 행이 바뀌어 409가 오면 이전 결과/경로를 지우고 **처음부터 다시 검색**을 제시합니다. 실패를 0건으로 표시하거나 자동으로 첫 페이지를 요청하지 않습니다. 429는 기다린 뒤 직접 재시도합니다.
- **앨범에서 보기**는 기존 카탈로그 앨범 상세 API/화면을 엽니다. 선택한 Track UUID가 현재 상세 페이지에 있는지 다시 확인한 뒤 곡을 표시하고 기존 개인 저장 API를 사용합니다. 현재 위치가 달라 페이지에 없으면 오류로 보류합니다. 제목/표시 번호로 다른 곡을 대신 선택하지 않습니다. 표시된 최신 목록을 보고 사용자가 저장을 누릅니다.
- **검색에서 선택한 곡** 표식으로 대상 행을 찾을 수 있습니다. 중복 저장/응답 유실은 기존 개인 내용 보존·명시적 최신 상태 확인 규칙을 유지합니다. 앨범에서 돌아오면 검색어/출처만 남고 결과는 새로 검색해야 합니다.
- 원문 링크는 검증된 **소속 앨범** URL입니다. 음악 재생이나 청취 기록을 만들지 않습니다. 공용 검색 응답 자체로 개인 저장을 만들지 않습니다.

## 응답·세션·보관 경계

`web/catalog-track-response.ts`는 합성 종류·요청과 같은 정규화 검색어/출처·페이지 크기/커서·UUID·행 중복·현재 위치·미확인 값·시각·앨범 URL/키를 검증합니다. 잘못된 자료는 화면/링크에 반영하지 않습니다. 원문 문자열은 React 텍스트로 렌더링하고 HTML을 실행하지 않습니다.

`catalogTrackApi`는 검색과 검색에서 연 앨범 조회/저장에 실제 쿠키 및 필수 UI 세션 조건을 보냅니다. 성공 응답의 사용자/세션 헤더와 성공/실패 뒤 현재 쿠키의 실제 세션을 모두 확인합니다. 기존 `forUser`도 인증된 세션 ID를 응답 헤더에 제공합니다. 헤더는 인증 수단이나 임의 사용자 선택 수단이 아닙니다. 다른 창의 새 로그인은 기존 서버 세션을 자동 폐기하지 않아도 UI의 현재 쿠키 재검사가 이전 결과 노출을 막습니다.

보관 기한은 곡 목록/앨범 제목 중 가장 이른 기한에서 서버의 checkedAt과 요청·세션 재확인에 걸린 시간을 빼 계산합니다. 클라이언트 시계가 서버와 같다고 가정하지 않습니다. 표시 중에는 단조 시계와 로컬 타이머로 기한 종료를 확인하며 앨범 상세로 이동해도 원래 검색의 보수적인 기한을 넘겨 유지하지 않습니다. 기한이 없다는 표시는 합성 자료에만 적용됩니다.

검색어/출처 변경·취소·닫기·화면 숨김·다시 초점 받기·오프라인은 요청과 결과/커서/선택을 제거합니다. 취소 뒤 늦은 성공/401을 반영하지 않습니다. 연결 복구 뒤 자동 검색하지 않으며 실제 세션 확인 뒤 사용자가 다시 검색합니다. 로그아웃·401·세션 전환은 앱의 세션 경계에서 검색어를 포함한 상태를 제거합니다. 검색어와 페이지 경로는 메모리에만 있으며 저장소·Service Worker·오프라인 쓰기 큐에 넣지 않습니다.

## 검증 범위

`tests/catalog-track-ui.test.ts`는 실제 서비스 응답의 표시 검증, 형식/종류/URL/페이지 오류와 짧은 다국어 입력, 서버 기준 수명 계산을 검사합니다. `tests/browser/track-search.spec.ts`는 1440×1000과 360×800 Chromium에서 실제 임시 로그인과 SQLite 검색/앨범/개인 저장 API를 사용합니다.

새 시나리오는 검색·출처 필터·정상 0건·반복 번호/미확인 길이·이전/다음 커서·26번 곡의 상세 페이지 선택·이중 클릭/저장 응답 유실 후 재확인·실제 제거 뒤 409를 확인합니다. 잘못된 URL/자료 종류/요청 결과, 표시 중 만료와 세션 확인 대기 중 만료, 입력 변경/취소/닫기 뒤 늦은 성공/401, 오프라인 복귀·숨김·429·세션 조회 실패·응답 헤더 불일치·성공/실패 중 다른 계정 쿠키도 검증합니다. 가로 넘침과 검색/저장/변경 화면 캡처를 확인합니다.

`tests/browser/track-search-fixture.ts`와 그 조작 endpoint는 전용 임시 E2E 서버에만 있습니다. 제품 서버/정책·환경 변수에 fixture 우회 경로를 추가하지 않습니다. 실제 소스·운영 DB/계정은 사용하지 않으며 새 스키마/의존성은 없습니다. 실제 모바일 기기·Safari·원격 HTTPS·배포 동시 부하는 별도 범위입니다.
