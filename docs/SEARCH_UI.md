# 통합 검색 화면

2026-10-24. 메뉴의 **음악 검색**에서 앨범 이름과 선택한 외부 소스를 [검색 API](SEARCH_API.md)에 보냅니다. React 화면을 연결했으며 **실제 소스 수집은 계속 비활성**입니다. 현재 제품 응답은 로컬 `sample_kind_unavailable`과 선택한 KHInsider·Zophar의 `policy_disabled`입니다. 정상 검색 0건으로 표시하지 않습니다.

## 사용과 결과 구분

- 처음에는 외부 소스를 선택하지 않습니다. 검색 버튼을 누를 때만 요청하며 입력 중 자동 검색·화면 진입 시 검색은 없습니다. 소스를 선택하지 않으면 로컬만 요청합니다.
- 로컬 카탈로그와 각 소스 결과를 별도 구역에 표시합니다. 같은 제목도 합치지 않고 출처 식별명으로 구분합니다. 개인 북마크·메모·저장 여부는 검색 대상에 포함하지 않습니다.
- 정상 0건, 조회 실패, 정책 비활성, 부분 결과, 보관된 자료, 최신 확인이 필요한 이전 자료를 구분합니다. 취득 시각·보관 기한, 갱신 실패와 원문 표시 개수를 표시하며 전체 고유 앨범 수로 합산하지 않습니다.
- 로컬은 현재 채택된 앨범 제목으로 조회하며 출처에서 재확인하지 않은 자료임을 안내합니다. 12개 단위 이전/다음 조회는 외부 소스를 제외한 요청으로 바꾸고 기존 원격 결과를 제거합니다.
- 소스별 **다시 검색**은 해당 소스 하나와 로컬을 새로 조회합니다. 선택 목록도 이에 맞춰 바꾸며 이전 소스 결과를 재검사 없이 합치지 않습니다. HTTP 오류 뒤의 **다시 검색**은 직전 요청을 명시적으로 반복합니다.
- 소스 `retryAt`과 HTTP `Retry-After` 동안 버튼을 비활성화합니다. 시간이 지나도 자동 재전송하지 않습니다. 같은 화면에서 검색어를 바꿔도 알려진 대기 시간은 유지됩니다. 서버의 요청 제한이 최종 기준입니다.
- **상세 보기**는 선택한 소스/앨범 키로 상세 창을 열어 별도로 조회합니다. 상세 제목·출처 주장·수록 순서/반복 번호·미확인 길이를 표시하며 검색 표시명은 유지합니다. 검색/상세 요청 제한 대기 시간은 공유합니다. [상세 화면 계약](SOURCE_ALBUM_UI.md)
- 원격 다음 페이지는 존재 여부만 안내합니다. 미지원 추가 수집·상세 선취득·검색 결과 직접 저장·앱 내 재생은 제공하지 않습니다. 원문 링크를 열어도 청취 기록을 생성하지 않습니다.
- **직접 북마크**는 기존 수동 입력 창을 엽니다. 검색 결과를 공용 카탈로그에 적재하거나 개인 제목으로 자동 복사하지 않습니다.

## 취소와 로그인 경계

`web/MusicSearch.tsx`는 요청별 AbortController와 순서 번호를 사용합니다. 검색문/소스 선택 변경, 검색 취소, 화면 이탈, 로그아웃 시작, 오프라인/연결 재확인 때 요청과 결과를 제거합니다. 화면이 숨겨지거나 창에 다시 초점이 돌아와도 결과를 제거하고 수동 재검색을 요구합니다. 화면을 벗어났다 다시 들어오면 검색문과 선택도 초기화됩니다.

오프라인에서는 검색문/선택만 메모리에 남습니다. 온라인 복귀 시 앱의 실제 세션 확인이 끝나야 화면을 다시 사용할 수 있으며 이전 검색은 자동 재실행하지 않습니다. 로그아웃 실패 시에도 검색 초안과 결과는 지웁니다. 401·세션 전환은 부모 앱이 화면 전체를 제거합니다.

`web/api.ts`의 검색 클라이언트는 다음 순서로 처리합니다.

1. 같은 origin 쿠키와 현재 `X-LoopShelf-Session` 조건으로 POST합니다.
2. 응답의 사용자·세션 헤더를 현재 화면과 비교합니다.
3. 현재 쿠키로 `/api/auth/get-session`을 새로 조회하여 사용자와 세션 ID를 다시 비교합니다. 다른 창의 로그인만으로 서버의 기존 유효 세션이 폐기된다고 가정하지 않습니다.
4. 검색문·선택 소스와 자료 종류/sampleKind를 검사한 뒤 결과를 표시합니다. 현재 세션을 확인하지 못하면 보유한 결과도 표시하지 않습니다.

두 요청의 클라이언트 대기는 합쳐서 15초이며 서버 검색 자체의 12초 제한을 변경하지 않습니다. 취소한 요청의 늦은 성공/401은 새 화면의 결과나 로그인 상태를 바꾸지 않습니다. 메모리 외에 검색문·응답을 보관하지 않으며 localStorage/sessionStorage/IndexedDB·Service Worker 캐시나 오프라인 큐를 추가하지 않습니다. 공유 검색 타입은 브라우저에서 서버의 메타데이터 검증 구현을 불러오지 않도록 파서 DTO 타입에 의존합니다.

## 표시 안전성과 검증 경계

제목과 안내는 React 텍스트로 표시합니다. 앨범 주소는 고정 소스의 정규 URL·원본 키와 일치해야 링크가 되고, 검색 페이지 링크도 HTTPS·고정 origin/경로를 검사합니다. 원문 HTML·스크립트·표지·오디오·iframe을 로드하지 않습니다. 합성 응답은 화면 전체와 항목마다 합성 자료로 표시하며 자료 종류가 섞이면 결과를 거절합니다.

`tests/browser/search.spec.ts`는 데스크톱 1440×1000·모바일 360×800의 실제 임시 로그인 세션으로 제품의 정책 비활성 응답부터 확인합니다. 이후 성공·캐시·부분 결과·0건·갱신 실패·429·timeout·세션 경합은 브라우저의 합성 응답으로 검증합니다. `tests/browser/search-fixture.ts`는 제품 코드에서 사용하지 않으며 서버 정책을 열거나 카탈로그에 적재하지 않습니다. 소스 요청은 브라우저 테스트에서 차단하고 0건임을 확인합니다.

이중 클릭, 로컬 페이지 이동, 출처별 재시도 범위와 cooldown 종료 후 자동 요청 없음, HTML/위험 링크 비활성, sampleKind 불일치, 세션 확인 실패, 입력 변경/취소/이탈 뒤 늦은 응답, 오프라인 복귀, 다른 계정 쿠키로의 전환, 응답 세션 불일치/401, 실패·성공 로그아웃 뒤 초안 제거, 직접 북마크 이동을 검사합니다. 화면 캡처와 가로 넘침을 두 크기에서 확인합니다. 실제 사이트 성공·휴대전화 실기기·Safari·배포 부하는 별도 검증입니다.

검증 결과: `npm run check`의 strict 타입 검사·프로덕션 빌드·268개 Node 테스트, 최종 변경 후 타입 검사와 `npm run test:e2e`의 전체 13개 시나리오를 통과했습니다. 스키마·운영 DB·계정·소스 정책은 변경하지 않았습니다.
