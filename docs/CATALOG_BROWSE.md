# 소스 독립 카탈로그 탐색과 저장

구현일: **2026-10-24**. 현재 서비스가 관리하는 합성 Album·현재 Track을 로그인한 사용자가 탐색하고 자기 라이브러리에 저장합니다. 실제 사이트 검색·수집·재생을 켜지 않으며 운영 서버는 fixture를 자동 적재하지 않습니다. 새 설치에 관리 앨범이 없으면 빈 탐색 화면을 보여줍니다. 외부 수집은 계속 `policy_disabled`입니다.

## 읽기 API

모든 경로는 실제 Better Auth 세션을 요구합니다. `forUser`가 인증부터 동기 조회까지 `withDatabase`로 직렬화하고, 읽기 트랜잭션에서 공용 메타데이터와 해당 사용자의 저장 여부를 함께 읽습니다. 응답은 `no-store`, UI 요청은 `X-LoopShelf-Session` 사전 조건을 사용합니다. 사용자 ID 입력과 알 수 없는 필드는 거절합니다.

| 경로 | 입력 | 응답 |
| --- | --- | --- |
| `GET /api/catalog/albums` | `q`, `sourceId=khinsider\|zophar`, `limit`, `offset` | `{ items: CatalogEntry[], nextOffset }` |
| `GET /api/catalog/albums/:id` | Album UUID, `limit`, `offset` | `{ album, trackState, tracks, nextOffset }` |
| `GET /api/library/catalog/:id/source-candidates` | 소유한 LibraryItem UUID, 목록과 같은 필터 | `{ target, itemId, version, remainingSlots, items, nextOffset }` |

`CatalogEntry`는 `{ entity, savedItemId }`입니다. `savedItemId`는 현재 계정의 개인 ID 또는 null이며, 공용 탐색 결과에 개인 제목·메모·즐겨찾기를 포함하지 않습니다. 같은 앨범을 보는 다른 계정에는 그 계정의 저장 여부만 표시합니다. 후보 API의 `target`은 소유권을 검사한 대상의 최신 `CatalogLibraryItem`이며 연결 전 개인 제목과 수정 버전을 다시 확인하는 용도입니다. 다른 계정의 대상은 404입니다. 공유 타입은 `src/shared/catalog-browse.ts`에 있습니다.

목록·후보 검색은 현재 채택한 앨범 제목의 NFKC 리터럴 부분 검색입니다. `%`, `_`, 따옴표를 검색 구문으로 해석하지 않고 메모·미채택 주장·과거 제목은 검색하지 않습니다. 제목 정규화값 → source ID → 원본 키 → 내부 ID 순으로 정렬합니다. 별도 검색 인덱스나 메타데이터 복사본은 추가하지 않았습니다. 앨범 후보를 먼저 선택하고 현재 관찰별 binding 키로 수록곡을 읽습니다. 합성 1만 앨범/10만 트랙에서의 조회 개선과 p95는 [성능 문서](CATALOG_PERFORMANCE.md)에 기록합니다.

페이지 기본 12개, 최대 100개, offset 0–100,000, 검색어 최대 200자입니다. 한 번 더 읽어 다음 페이지 유무를 판정하며 페이지 간 카탈로그 변경에 대한 고정 스냅샷은 제공하지 않습니다. 상세의 페이지 이동은 수록곡에만 적용됩니다.

## 노출과 정체성

- `catalog_album_state`가 있는 관리 앨범 중 active Entity와 unverified/available 출처만 탐색합니다. unverified는 실제 재생이나 수집 허가를 뜻하지 않습니다. 모든 응답에 합성 자료·소스별 임시 정체성 표시를 유지합니다.
- 제거 영수증이 있거나 차단·이용 불가인 앨범은 목록·후보에서 제외하고 직접 상세 조회도 404입니다. 누락한 Track은 상세 수록곡에 포함하지 않습니다. 기존 개인 저장은 별도 개인 API에서 보존 상태로 조회·편집·삭제할 수 있습니다.
- 수록 위치는 현재 `catalog_track_binding`에서 읽습니다. 반복 표시 번호와 원문 디스크/길이의 미확인 값은 유지합니다. 표시 번호를 Track ID로 사용하지 않습니다.
- 상세를 아직 적재하지 않은 검색 요약은 `not_loaded`와 빈 목록입니다. 새로운 트랙 관찰이 검토 중이면 `review_required`와 **현재 채택된** 목록을 표시합니다. 이 화면에서 자동 대응이나 채택은 하지 않습니다.
- `src/catalog/entities.ts`의 공통 projection을 개인 저장 서비스와 공유합니다. 탐색 서비스는 별도 가용성 필터를 적용하여 개인 보존용 placeholder를 공용 검색에 노출하지 않습니다.

## 화면과 쓰기

**저장한 카탈로그 → 카탈로그 둘러보기 → 앨범 보기**에서 앨범과 각 곡을 저장합니다. 검색·출처 필터와 페이지 이동, 상세 요약만 있는 상태와 미확인 길이, 내 계정의 저장됨 표시를 제공합니다. 상세에서 목록으로 돌아가면 적용한 검색 조건을 유지합니다.

저장은 기존 `POST /api/library/catalog`에 Entity UUID만 보냅니다. 제목을 개인 필드에 복사하지 않으며 중복 저장은 기존 제목·메모·즐겨찾기를 보존합니다. 요청 중 이중 클릭을 막고, 응답 유실 시 추가 저장을 잠근 다음 최신 상세를 명시적으로 읽어 저장 여부를 확인합니다. 쓰기를 자동 재전송하지 않습니다.

**출처 보기 → 추가 출처 선택**은 원래 출처와 이 계정에서 이미 추가 연결한 모든 출처를 제외합니다. 별도로 저장한 앨범도 후보가 될 수 있으며 다른 계정의 연결은 영향을 주지 않습니다. 추가 출처 20개 한도, 대상 앨범 가용성, Track 연결 불가를 검사합니다. 후보 목록은 유사도 추천이나 동일 음악의 확정 결과가 아닙니다.

같은 제목의 앨범도 원본 키인 출처 식별명으로 구분합니다. 후보 선택 후 현재 개인 제목·선택한 앨범·소스·출처 식별명을 확인하고 **개인 연결 확인**을 눌러 기존 연결 API에 후보 조회 시점의 개인 버전과 SourceEntity ID를 보냅니다. 서버는 최신 버전·현재 가용성·계정별 점유·한도를 다시 검사합니다. 충돌이나 응답 유실 후 선택을 비우고 새 후보 조회 전에는 다시 연결하지 못하게 합니다. 재조회는 부모 출처 화면과 저장 목록에도 반영합니다. 별도 저장 항목과 메모를 합치거나 숨기지 않습니다.

모든 개인 상태는 메모리에만 두고 기존 세션/오프라인 gate를 공유합니다. 화면 이탈 시 진행 중 요청을 취소합니다. 취소한 쓰기는 서버에서 완료됐을 수 있으므로 다시 열 때 서버를 조회합니다. 중첩 대화상자 없이 목록/상세와 출처 관리/선택 사이를 이동합니다. 북마크 JSON v1과 60초 복구는 직접 입력 북마크 전용이며 카탈로그 개인 자료는 [별도 JSON](CATALOG_TRANSFER.md)으로 이식합니다. 미연결 개인 항목을 공용 탐색 자료로 추가하지 않습니다. 내 미연결 저장의 Entity ID가 현재 탐색 자료와 같으면 중복 저장 대신 기존 저장을 표시하며 자동 재연결하지 않습니다. 추가 출처 후보에서는 일반/미연결 개인 항목이 점유한 출처를 모두 제외합니다.

## 검증 범위

`tests/catalog-library.test.ts`에 탐색 관련 5개 테스트를 추가했습니다. 실제 두 계정 로그인, 캐시 금지·세션 사전 조건·소유권·엄격한 쿼리, 계정별 저장 표시, 정규화 검색·페이지 이동·소스 요약, 채택/검토 중 수록곡, 반복 번호, 제거·차단 비노출, 개인별 후보 제외와 최신 버전/가용성 재검사를 검증합니다. 기존 20개 연결 한도 테스트에 후보 고갈도 포함했습니다.

브라우저 검증 범위와 최종 결과는 [FRONTEND.md](FRONTEND.md#재현-가능한-검증)에 기록합니다. 테스트는 임시 계정·DB와 합성 자료만 사용하며 외부 사이트를 호출하지 않습니다. 실제 모바일 기기·Safari·HTTPS 배포·실사이트 통합은 이번 범위가 아닙니다. 대규모 합성 조회는 별도 [측정 조건](CATALOG_PERFORMANCE.md)으로 검증했습니다.
