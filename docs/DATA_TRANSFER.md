# 개인 북마크 JSON 내보내기·가져오기

검증일: **2026-10-22**. 직접 입력한 북마크와 `bookmark_connection`의 개인 그룹을 이식합니다. 공용 카탈로그와 인증 데이터는 대상이 아닙니다.

**이 문서의 `loopshelf-bookmarks` v1에는 카탈로그 개인 자료가 포함되지 않습니다.** 카탈로그는 별도 [카탈로그 JSON v2(v1 입력 호환)](CATALOG_TRANSFER.md)으로 내보내고 복원합니다. 화면에서 두 파일을 각각 보관해야 합니다. 북마크 JSON을 가져와도 카탈로그 개인 항목을 바꾸지 않으며 일반/미연결 개인 ID 충돌은 거절합니다. 설치 전체 보존은 계속 [SQLite 백업/복원](OPERATIONS.md)을 사용합니다.

## 화면에서 사용하기

**내 계정 → 데이터 관리**에서 사용합니다.

1. **JSON 내보내기**를 누르면 현재 계정의 원래 북마크 전체를 다운로드합니다. 목록의 검색·즐겨찾기·페이지 필터와 무관하며 연결된 멤버도 포함합니다. 브라우저 다운로드 목록에서 파일을 확인합니다.
2. **LoopShelf JSON 파일**을 선택한 뒤 **파일 검사**를 누릅니다. 파일 선택은 브라우저 메모리에서 읽기만 하며, 검사할 때 서버로 전송합니다. 파일명과 원본 파일을 서버 디스크에 보관하지 않습니다.
3. 추가·동일 항목·충돌 건수와 새 출처 연결 수를 확인합니다. 충돌이 없을 때 **확인하고 가져오기**를 누르면 한 번에 저장합니다. 창을 닫거나 다른 파일을 선택하면 검사 결과가 사라집니다.
4. 통신 오류가 발생하면 같은 파일을 다시 검사합니다. 서버 저장이 이미 끝났다면 동일 항목으로 판정하므로 중복을 만들지 않습니다.

파일에는 개인 제목·메모·즐겨찾기가 들어 있습니다. 비밀번호·세션·사용자 ID·이메일·음원·외부 메타데이터·감사 기록은 포함하지 않습니다. 브라우저 저장소와 Service Worker에도 파일을 남기지 않으며 로그아웃·세션 전환 시 선택한 파일과 검사 결과를 제거합니다. 사용자가 내려받은 파일은 브라우저의 다운로드 위치에 남습니다.

## 복원 규칙

- 파일에 기록된 LibraryItem ID와 Bookmark Entity ID를 유지합니다. 복원 대상 소유자는 현재 로그인 세션에서 정합니다.
- 제목·정규 앨범 URL·메모·즐겨찾기·생성/수정 시각과 연결 시각을 보존합니다. 수정 충돌 검사용 `version`은 로컬 상태이므로 내보내지 않고 복원 시 새 값을 부여합니다.
- 같은 ID·내용·날짜·연결을 가진 기존 항목은 그대로 두고 건너뜁니다. 가져오지 않은 기존 항목도 유지합니다.
- 같은 ID의 내용/연결이 다르거나, 같은 URL을 다른 ID로 저장했거나, ID가 다른 계정/카탈로그에서 사용 중이면 충돌입니다. 자동 덮어쓰기·URL 기준 합치기·ID 재발급은 제공하지 않습니다.
- 충돌이 하나라도 있으면 **전체를 저장하지 않습니다**. 화면에는 처음 50개 충돌만 표시하며 다른 사용자의 내용이나 소유자 정보는 노출하지 않습니다.
- 기존 그룹에 새 출처를 덧붙이는 등 현재 연결을 변경하는 가져오기도 충돌로 처리합니다. 현재 그룹과 완전히 같은 그룹을 건너뛰고 새로운 그룹을 함께 추가하는 것은 가능합니다.
- 같은 설치의 다른 계정으로 복사하면 사용 중인 ID와 충돌합니다. 새 설치에서는 먼저 계정을 만들고 로그인한 뒤 같은 파일의 ID를 유지해 복원할 수 있습니다.

한도는 **UTF-8 JSON 8 MiB, 원래 북마크 5,000개, 그룹당 대표 포함 20개**입니다. 가져온 뒤 선반 전체도 JSON 한도에 들어와야 합니다. 수동 북마크 추가로 한도를 넘은 경우 JSON 내보내기는 오류를 반환하며 일부 항목만 내보내지 않습니다. 큰 라이브러리와 설치 전체 복구에는 [SQLite 백업/복원](BACKEND.md#백업과-복원)을 사용합니다. 빈 파일 목록은 유효한 0건 작업이며 현재 선반을 비우지 않습니다.

## 파일 포맷 v1

```json
{
  "format": "loopshelf-bookmarks",
  "schemaVersion": 1,
  "exportedAt": "2026-10-21T00:00:00.000Z",
  "bookmarks": [],
  "connections": []
}
```

`bookmarks`의 각 객체는 아래 필드를 모두 포함합니다. 알 수 없는 필드, 형식 버전과 데이터 유형은 거절합니다.

| 필드 | 값 |
| --- | --- |
| `id`, `entityId` | 서로 구분되는 UUID. 파일 안에서 중복 금지 |
| `title` | 앞뒤 공백 없는 1–300자 제목, 제어 문자 금지 |
| `url` | 지원하는 KHInsider/Zophar의 정규 HTTPS 앨범 URL. 쿼리·fragment·임의 호스트 금지 |
| `note` | 최대 10,000자, NUL·잘못된 Unicode 거절 |
| `favorite` | boolean |
| `createdAt`, `updatedAt` | UTC ISO 시각, 밀리초 3자리. 생성 시각 ≤ 수정 시각 |

`connections`는 `{ parentId, memberId, connectedAt }` 객체의 배열입니다. 두 ID 모두 같은 파일의 북마크를 가리켜야 하며 자기 자신·중복 멤버·중첩·순환은 거절합니다. `connectedAt`도 밀리초 3자리 UTC ISO 시각입니다. sourceId/externalKey는 검증된 URL로 재구성하며 임의 값을 가져오지 않습니다. 파일 포맷에는 인증 주체를 지정하는 필드가 없습니다.

## HTTP와 트랜잭션

모든 경로는 로그인 쿠키, 기존 Host/Origin 검사와 `X-LoopShelf-Session` 사전 조건을 적용하며 응답은 `no-store`입니다.

| 메서드 / 경로 | 입력 / 결과 |
| --- | --- |
| `GET /api/library/export` | 쿼리 없음. 전체 JSON 및 `Content-Disposition: attachment` |
| `POST /api/library/import/preview` | `{ archive }` → `{ addCount, skipCount, connectionCount, conflictCount, conflicts, token }` |
| `POST /api/library/import` | `{ archive, token }` → `{ added, skipped, connectionsAdded }` |

검사는 쓰기를 하지 않습니다. 서버는 사용자·검증한 파일 내용·현재 개인 북마크/연결/수정 버전·10분 만료 시각에 묶인 HMAC 토큰을 반환합니다. 충돌이 있으면 토큰은 null입니다. 확인 요청에서 같은 조건을 다시 검증하고, 다른 사용자의 동시 가져오기에 따른 ID 충돌도 다시 확인합니다. 토큰은 인증 수단이 아니며 유효한 쿠키가 항상 필요합니다.

`400 invalid_archive`는 지원하지 않는 형식/값/관계, `413 archive_too_large`는 파일·건수·복원 결과 한도, `409 preview_stale`은 변경된 파일/선반·토큰 만료/불일치, `409 import_conflict`는 확인 시점의 충돌입니다. 요청 envelope 오류는 `400 invalid_input`일 수 있습니다. 전송 자체가 본문 한도를 넘으면 `413 invalid_request`입니다. 가져오기 두 경로만 본문 한도를 8 MiB + envelope 여유 4 KiB로 늘렸고 일반 CRUD는 32 KiB를 유지합니다.

현재 세션 조회와 작업은 `withDatabase`로 직렬화합니다. 확인 시 `BEGIN IMMEDIATE` 안에서 재검증 → 새 Entity/Bookmark/LibraryItem → 검색 트리거 → 출처 연결/감사 기록 순으로 처리합니다. 하나라도 실패하면 ID 할당 상태를 포함한 모든 쓰기를 롤백합니다. 원본 업로드 파일은 DB에 저장하지 않습니다.

`0004_import_revisions.sql`의 `library_revision`은 이미 사용한 로컬 수정 버전의 상한을 삭제 후에도 유지합니다. 복원된 행은 그보다 큰 버전을 받아 삭제 전 편집 창에서 저장/삭제할 수 없게 합니다. 마이그레이션은 기존 행을 바꾸지 않으며 초기 상한은 현재 버전과 초기화 시각을 기준으로 합니다. 연결의 원래 시각은 복원하지만 새 감사 이벤트 시각은 실제 복원 작업 시각입니다.

## 확인한 범위

다른 설치로의 JSON 왕복, 원본 ID·개인 내용·연결·검색 보존, 페이지 밖과 연결 멤버 포함, 동일 파일 재시도, 충돌/권한/위조 토큰/만료/동시 요청, 잘못된 JSON·URL·관계·Unicode·UTF-8 크기 한도, 트랜잭션 실패 롤백과 기존 연결 선반의 0003 → 0004 마이그레이션도 검사했습니다. 데스크톱·모바일 Chromium에서는 실제 다운로드한 파일의 복원, 충돌 안내, 검사 후 선반 변경, 저장 응답 유실 후 재검사까지 검증했습니다. 외부 사이트 요청은 없습니다.
