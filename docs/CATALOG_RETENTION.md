# 카탈로그 자료 종류와 보관 수명

기준일: **2026-10-24**. `0012_catalog_retention.sql`과 `src/catalog/retention.ts`는 자료 종류 격리·보관 만료·정책 철회의 저장 모델입니다. 실행 검증에는 합성 DTO, 임시 SQLite와 로컬 브라우저 계정만 사용했습니다. **제품 live 수집/저장은 여전히 비활성입니다.** 저장 HTTP는 [별도 합성 검증](SOURCE_SAVE_API.md)으로 연결했으며 React 저장 UI는 후속입니다. 2026-10-25에 개인 DTO/JSON v2와 내부 저장의 수명 연결을 추가했습니다. 공용 탐색/live 활성화는 후속이며 [현재 종류 계약](CATALOG_KINDS.md)을 따릅니다.

## 자료 종류와 관찰 수명

`catalog_source_kind`는 SourceEntity별 `synthetic` 또는 `live-capture`를 고정합니다. 동일한 source/external key를 다른 자료 종류로 다시 적재하면 거절하며 자동 승격·URL 매칭·UUID 교체를 하지 않습니다. 제거된 소스에도 종류 표시는 남습니다. 기존 관리 자료와 제거 영수증은 마이그레이션에서 synthetic으로 이관합니다.

`catalog_observation`에는 `retention_revision`, `expires_at`, `content_state`를 추가했습니다. live-capture는 정책 revision과 취득 시각보다 뒤인 유효한 기한을 반드시 갖습니다. 기존 합성 fixture는 두 필드가 null인 상태로 보존합니다. null은 실제 자료의 무기한 보관 허가가 아닙니다. 원래 정책/기한을 부여한 뒤에는 같은 관찰의 재시도로 연장·삭제·교체할 수 없습니다.

합성 수명 검증용 `ingestRetainedSyntheticInTransaction`은 호출자가 소유한 `withDatabase`와 동기 트랜잭션에서만 사용합니다. lease 검증 실패는 새 Entity/관찰/출처 종류까지 롤백합니다. 이 경계는 실제 보관 허가를 대신하지 않습니다. 합성 기한은 취득 뒤 최대 30일 이내이며, 실제 정책별 보관 한도는 [입력·허용 계약](SOURCE_SAVE.md)의 별도 검증 대상입니다.

## 만료, 철회, 영구 제거

| 상태 | 처리 | 이후 새 관찰 |
| --- | --- | --- |
| active | 허용 수명 내 메타데이터 사용 | 기존 중복/최신 관찰 규칙 적용 |
| expired | 기한 도달 시 외부 내용 정리 | 같은 앨범 UUID 유지 가능, 곡 대응은 별도 검토 |
| policy_revoked | live 보관 정책이 불허/미확인 또는 revision 불일치이면 내용 정리 | 새 허용 근거·새 관찰 필요, 옛 관찰 재활성화 금지 |
| catalog_removal | 권리/정책 제거 영수증과 기존 제거 처리 | 같은 소스 키 재적재 금지 |

`reconcileCatalogRetention`은 동기 작업이며 호출자는 DB 경계를 소유해야 합니다. 공용 카탈로그/개인 목록·단건·새 저장·출처 연결·개인 JSON에서 먼저 검사하고, 시작 시와 10초 정리 주기에도 실행합니다. 네트워크 대기는 없습니다. 마지막 공개 조회 검사는 기존 통합 검색 서비스 경계를 따릅니다. 상속된 합성 관찰은 기한을 새로 추측해 부여하지 않습니다.

만료/철회 시 관찰 JSON, 경고, 검색 맥락, 해당 관찰의 외부 assertion, URL 이력과 최초 트랙 DOM locator를 정리합니다. locator는 트랙 UUID로 대체합니다. 최소 SourceEntity 참조 URL/키, 관찰 UUID·취득 시각·해시·정책/기한, 채택 포인터와 ID만 담은 채택 영수증은 남깁니다. 조회·채택 재시도로 지워진 관찰 내용을 되살릴 수 없습니다.

현재 앨범 제목 근거가 만료되면 제목을 `보관이 종료된 앨범`으로 바꿉니다. 트랙은 **실제로 마지막 채택한 관찰**이 만료되었을 때만 제목/번호/디스크/길이를 정리합니다. 오래된 최초 관찰이 만료되어도 새로 채택한 제목을 지우지 않으며, 최신 근거가 만료되었을 때 오래된 근거로 자동 되돌리지 않습니다. 채택 대상은 기존 규칙상 취득 시각이 증가하는 최신 상세 관찰입니다. 정리는 영향을 받은 앨범의 수록곡으로 제한합니다.

공유 출처·curated assertion·별도 게임/녹음 연결이 있는 경우 자동 판단으로 지우지 않고 `removal_conflict`로 전체 정리를 롤백합니다. 해당 검사를 끝내지 못한 읽기/서버 시작도 실패하므로 확인하지 못한 내용은 성공 응답으로 나가지 않습니다. 운영자의 근거 검토가 필요하며, 기존 운영자 전용 [영구 제거 계약](CATALOG_REMOVAL.md)과 구분합니다.

## 개인 선반과 새 관찰

Album/Track/SourceEntity/개인 저장 UUID, 메모, 즐겨찾기, title override, 개인 수정 버전과 추가 출처 판단을 유지합니다. null title override는 종료 안내 제목으로 계산하고 사용자가 직접 쓴 제목은 보존합니다. 개인 저장 화면은 `외부 정보 보관 종료 · 개인 내용 유지`를 표시합니다. 기존 개인 내용의 편집·해제·삭제와 동일 저장/연결의 중복 확인은 가능하지만 새 저장/연결은 거절합니다.

만료 앨범은 공개 탐색·로컬 검색·출처 후보에서 제외합니다. 운영 상세/관찰 조회는 `content_expired`로 거절합니다. 이후 새로운 상세가 들어오면 앨범 UUID와 개인 행을 보존합니다. 만료된 baseline의 곡 목록과 새 목록의 해시가 같아도 자동으로 대응시키지 않습니다. 현재 수록곡은 비워 두고 `review_required`로 보류하며, 운영자가 [명시적 트랙 채택](TRACK_ADOPTION.md)으로 기존 ID 또는 새 곡을 모두 선택해야 합니다. 상세 제목의 근거가 만료된 상태에서 더 최신인 검색 표시명을 받더라도 상세 제목을 덮어쓰지 않습니다.

## 현재 공개 경계와 JSON

공용 탐색과 제품 live 로컬 검색 미지원 경계는 유지합니다. 개인 DTO와 운영 상세/채택은 고정된 자료 종류를 사용하고, 만료된 외부 상세는 반환하지 않습니다. 개인 JSON은 모든 참조에 종류를 담은 v2로 내보내며 기존 synthetic v1을 가져올 수 있습니다. live 참조도 만료/제거/미연결 상태에서 개인 내용과 함께 보존하며 합성으로 바꾸지 않습니다. [종류·버전 계약](CATALOG_KINDS.md)

개인 JSON은 만료 전후 동일한 개인 ID/내용·최소 참조만 담습니다. 관찰 제목·길이·수록곡·정책/기한은 내보내거나 복원하지 않습니다. 만료가 검사와 확인 사이에 발생하면 참조 상태 서명이 달라져 `preview_stale`이 됩니다. 원래 참조가 남아 있으면 같은 개인 ID를 만료 상태로 복원하고, 참조가 없는 설치에서는 기존대로 미연결 자료로 보존합니다.

## 마이그레이션과 복원

0012는 외래 키를 끄거나 기존 마이그레이션을 수정하지 않습니다. 관찰 테이블을 교체하는 동안 참조 행을 같은 트랜잭션의 임시 테이블로 옮긴 후 원래 UUID·binding·origin·채택 영수증·assertion·개인 행을 복원합니다. 영구 제거 영수증과 이전 마이그레이션 체크섬도 보존합니다. 도중 실패 시 전체 마이그레이션을 롤백합니다.

온라인 백업과 새 경로 복원은 **생성한 복사본**에서 만료/현재 정책을 다시 검사합니다. 운영 원본이나 과거 백업 파일은 수정하지 않습니다. 복원은 세션·임시 인증 토큰·세션 소유 복구 영수증을 제거하고 재로그인을 요구하는 기존 규칙을 유지합니다. 백업 이후의 영구 제거 결정은 여전히 서비스 재개 전에 별도로 재적용해야 합니다. 0011 이전 백업은 일치하는 절차로 업그레이드한 뒤 최신 시작 검사를 통과해야 합니다.

이 모델은 SQLite에서 조회 가능한 내용의 정리를 검증합니다. 이전 백업 파일·스토리지 매체의 안전한 폐기나 물리적 흔적 삭제를 보장하지 않습니다. 실제 수집 활성화 전에 백업 파일 자체의 보관 기한과 운영 폐기 절차도 확인해야 합니다.

## 검증과 남은 단계

`tests/catalog-retention.test.ts`의 **13개 테스트**는 만료 후 검색/새 저장 거절·개인 내용과 버전 보존·새 관찰과 명시적 곡 채택·최신/과거 근거의 서로 다른 수명·중복 기한 연장 거절·영구 제거·공유 근거 충돌·JSON 검사 만료·0011 업그레이드/실패 롤백·새 경로 복원·자료 종류 충돌·정책 미확인 시 정리를 확인합니다. live-capture 테스트는 직접 만든 **스키마 시뮬레이션**이며 실제 캡처/허가/제품 live 쓰기 성공이 아닙니다. 데스크톱/모바일 기존 카탈로그 브라우저 흐름에 만료 안내, 개인 메모, 옛 제목 검색 제외와 탐색 제외를 추가했습니다.

보관 검사 비용은 `npm run bench:retention`으로, 전체 탐색은 `npm run bench:catalog`로 재현합니다. 부분 인덱스는 active lease만 포함하며 종류/기한 조건으로 조회합니다. 자료 분포·환경·원시 표본과 실행 계획은 [성능 문서](CATALOG_PERFORMANCE.md)에 기록합니다.

개인 DTO/JSON v2·내부 저장의 승인 수명 전달은 [후속 종류 계약](CATALOG_KINDS.md)으로 확장했습니다. 제품 live guard와 실제 사이트 정책은 닫힌 상태를 유지합니다. 다음은 저장 선택 확인과 인증된 저장 HTTP API이며, 활성화에는 별도 공용 live 경계·허용 근거·실사이트 검증이 필요합니다.
