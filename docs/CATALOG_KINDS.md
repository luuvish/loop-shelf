# 카탈로그 자료 종류·JSON v2·승인 수명 연결

기준일: **2026-10-25**. 개인 조회 DTO와 JSON 이식은 합성 자료와 외부 자료 참조를 구분합니다. 소스 저장 내부 흐름은 승인된 정책 revision/원래 기한을 관찰과 같은 트랜잭션에 기록합니다. **실제 사이트의 수집·보관 허가를 얻거나 제품 live 저장을 활성화한 작업은 아닙니다.** 0013은 이전 앱의 잘못된 자료 종류 해석을 막는 버전/새 참조 제약을 추가합니다. 0012까지의 적용 SQL은 수정하지 않았으며 운영 DB에 마이그레이션을 적용하지 않았습니다.

## 경계별 지원 범위

| 경계 | 현재 동작 |
| --- | --- |
| `ingestSynthetic` / `ingestSyntheticInTransaction` | 기존 합성 DTO 전용. 기존 fixture는 기한 없는 개발 자료로 유지 |
| `ingestRetainedSyntheticInTransaction` | 과거/현재 기한 정리를 시험하는 내부 합성 수명 검증용 |
| `ingestRetainedAlbumInTransaction` | 서버 소유 앨범 DTO와 명시적 lease 검증. live 요청은 별도로 고정 제품 보관 정책을 확인하므로 현재 `policy_disabled` |
| 소스 저장 서비스 | 실제 세션/선택 관찰/현재 정책을 확인한 합성 시험에 원래 보관 수명 연결. 제품 정책 unknown 및 live `storage_unavailable` guard 유지 |
| 운영 카탈로그 상세/관찰/채택 DTO | 실제 SourceEntity의 sample kind를 사용. 읽기 전 만료/정책 정리, 만료된 상세/관찰은 거절 |
| 개인 카탈로그 조회·수정·삭제·이식 | 원본/만료/제거/미연결 참조의 자료 종류와 개인 내용을 보존 |
| 공용 탐색·후보/통합 로컬 검색 | 기존 합성 탐색과 제품 live 로컬 미지원 유지. 실제 자료의 성공 검색으로 표시하지 않음 |
| 저장 HTTP/선택 확인 UI | [상세 사전확인·저장 HTTP](SOURCE_SAVE_API.md) 및 [React 저장 확인](SOURCE_SAVE_UI.md) 연결, 합성 성공만 검증. 제품 live 저장은 비활성 |

자료 종류는 `catalog_source_kind`에 고정된 SourceEntity 속성입니다. 동일 source/key의 합성 자료를 실제 자료로 승격하거나 새 UUID로 치환하지 않습니다. 개인 참조의 자료 종류도 정체성 비교에 포함하며, 같은 앨범/SourceEntity ID를 서로 다른 자료 종류로 주장하는 파일은 거절합니다. 실제 앨범이 있어도 URL/제목으로 다른 UUID에 대응시키지 않습니다. 새 개인 출처 연결은 같은 자료 종류의 앨범 사이에서만 가능하며 Track 출처는 여전히 소속 앨범 provenance입니다.

## 개인 DTO와 표시

`SavedCatalogEntity.sampleKind`는 `synthetic | live-capture`입니다. 관리 중인 자료는 DB의 고정값을 읽고, 원본 미연결 자료는 파일의 명시적 참조를 보존합니다. 예전 불변 detached JSON 행에 종류 필드가 없을 때만 기존 v1 계약대로 synthetic으로 해석합니다. 이를 위해 기존 개인 행의 ID/내용/버전/JSON을 다시 쓰지 않습니다. 알 수 없는 종류 값은 합성 기본값으로 바꾸지 않습니다.

보관이 종료된 live 앨범/곡도 `expired`와 안내 제목으로 개인 목록에 남고 편집/삭제/내보내기가 가능합니다. 영구 제거 후에는 `removed`와 고정 자료 종류를 유지합니다. 원본이 없는 `unresolved` 자료는 공용 Entity나 SourceEntity를 만들지 않습니다. 모든 읽기와 이식은 기존 세션/소유권·DB 직렬화·보관 수명 경계를 유지합니다.

개인 화면은 `합성 자료`와 `외부 자료 참조`를 표시합니다. 외부 자료 참조라는 표시는 원문 수집 성공·이용 허가·음원 재생 가능을 뜻하지 않습니다. 특히 가져온 파일의 종류는 개인 참조의 주장일 뿐이며 서버 정책이나 공용 출처 종류를 변경하지 못합니다. 카탈로그 둘러보기는 계속 합성 검증 화면입니다.

## JSON v2와 v1 호환성

새 export는 항상 다음 v2 형식입니다. 전체 파일에 한 가지 종류를 지정하지 않고 **원래 참조와 모든 추가 출처의 reference에 각각 sampleKind를 필수로 기록**합니다. 한 파일에 서로 다른 종류의 별도 개인 항목이 함께 있을 수 있습니다. 한 항목의 추가 출처는 원래 참조와 같은 자료 종류여야 합니다.

```json
{
  "format": "loopshelf-catalog",
  "schemaVersion": 2,
  "exportedAt": "2026-10-25T00:00:00.000Z",
  "items": []
}
```

각 reference는 `entityId`, `kind`, `albumId`, `source`, `sampleKind`를 포함합니다. source는 기존의 `id`, `sourceId`, `externalKey`, 정규 `pageUrl`입니다. 개인 ID/직접 작성한 제목·메모·즐겨찾기·원래 시각·추가 출처 판단을 보존합니다. 공용 제목·수록곡·길이·관찰·보관 정책/기한·제거 결정·인증은 내보내거나 복원하지 않습니다.

기존 v1은 최상위 `sampleKind: synthetic`, 종류 없는 참조라는 **원래 엄격한 형식**으로만 받습니다. 검증 후 내부 비교용 참조를 명시적 synthetic으로 정규화합니다. v1에 live 표시나 참조 종류 필드를 덧붙이는 것은 거절합니다. v2의 종류 누락·잘못된 종류·알 수 없는 버전·허가/외부 메타데이터 필드도 거절합니다. 기존 v1 파일을 그대로 다시 가져오면 동일 개인 항목은 건너뛰며, 이후 내보내기는 같은 ID/내용의 v2입니다. v2를 읽지 못하는 이전 앱에서는 새 파일을 가져올 수 없습니다.

파일 8 MiB·5,000항목·20개 출처 상한과 전체 거절 규칙은 유지합니다. 합친 선반을 v2로 내보낼 때의 크기도 검사합니다. 기존 스키마와 새 스키마를 서로 오인하지 않도록 검사 토큰은 정규화한 개인 내용 외에 **검증한 원래 파일의 버전과 참조 종류**도 포함합니다. 검사한 v1을 의미상 같은 v2로 바꾸어 확인하거나 종류를 바꾸면 `preview_stale`입니다. 만료/제거·현재 참조의 가용성 재검사와 원자적 롤백, 다른 계정의 ID 점유, 새 로컬 수정 버전 규칙도 유지합니다.

원본이 하나라도 없으면 항목 전체를 미연결로 보존합니다. 같은 원본 source ID가 알려져 있고 곡 ID만 없는 경우에도 원본의 고정 자료 종류와 비교해 충돌을 거절합니다. 가져오기는 보관 기한이나 관찰을 만들지 않으므로 만료·제거된 메타데이터를 되살리지 않습니다. [전체 이식 계약](CATALOG_TRANSFER.md)

## DB 버전과 이전 앱 차단

`0013_catalog_reference_kinds.sql`은 기존 v1 JSON/UUID/개인 버전을 다시 쓰지 않습니다. 새 detached 원래 참조와 추가 출처에 명시적 자료 종류를 요구하고, 추가 출처 종류가 부모 항목과 다르면 SQL에서도 거절합니다. 기존 v1 부모는 synthetic으로 해석합니다. 참조 수정은 원래 불변 제약으로 차단합니다.

새 JSON을 저장한 DB를 이전 코드가 열면 live 참조를 합성으로 해석할 수 있으므로, 종류 검사만 추가하는 데 그치지 않고 스키마 이력도 0013으로 올립니다. 기존 `assertMigrated`의 버전/체크섬 검사 때문에 0012까지만 아는 앱은 시작할 수 없습니다. 이전 코드로 돌아가려면 해당 코드에 맞는 백업도 새 경로에 복원해야 합니다. [업그레이드/복구](OPERATIONS.md)

## 승인 수명과 원자적 저장

`admitSourceAlbum`은 검증된 서버 상세와 `policyRevision`, `retainUntil`을 반환합니다. 내부 저장은 이를 `ingestRetainedAlbumInTransaction`에 전달합니다. 단독 트랜잭션 밖 호출·잘못된 lease·미래 취득/파싱·취득 뒤 30일을 넘는 기한·이미 끝난 기한은 거절합니다. 실제 허용 기간을 30일로 가정하는 것은 아니며, live 경로는 고정 제품 정책의 더 짧은 한도/현재 parser/revision도 검사합니다. 호출자로부터 허용 policy를 주입받지 않습니다.

관찰의 원래 기한은 취득 시각과 상세의 원래 만료에서 계산합니다. 재시도/개인 저장 시점에 기한을 연장하지 않습니다. 같은 관찰에 다른 revision/기한을 전달하면 충돌이며, 기존 합성 개발 관찰에 처음 제한을 부여하는 경우만 같은 트랜잭션에서 명시적으로 적용합니다. 새 관찰은 메타데이터·원래 lease를 동시에 INSERT하므로 live의 필수 수명 제약을 잠시 비우지 않습니다.

공용 관찰/Entity/자료 종류와 개인 저장은 한 immediate 트랜잭션에서 반영합니다. 개인 쓰기 실패나 마지막 정책/취소/기한 확인 실패는 lease까지 함께 롤백합니다. 만료된 baseline과 새 목록의 해시가 같더라도 저장 응답은 `review_required`이며 기존 곡을 자동 재연결하지 않습니다. 원래 ID·개인 내용·최초 origin과 명시적 트랙 채택 규칙은 유지합니다.

`src/source-save.ts`의 제품 정책은 unknown이고 서비스의 live 지원 guard도 유지했습니다. 이 단위의 성공 저장은 **합성 자료와 실제 임시 쿠키 세션**으로 검증한 것입니다. live 타입의 저장 성공, 허용된 공용 live 검색/선택, 실제 소스 정책과 활성화는 별도 완료 조건입니다.

## 검증

`tests/catalog-kinds.test.ts`의 13개 검사는 혼합 자료 종류 export·v1 파일/옛 DB 행 호환·미연결 live 참조·종류 충돌·토큰의 버전/종류 바인딩·만료/영구 제거 후 개인 복원·롤백·백업/재개·독립된 live 정책 거절·실제 세션 API·0013 업그레이드/실패 롤백·실제 이전 스키마 시작 검사 거절을 다룹니다. live 메타데이터는 `tests/helpers/catalog-live.ts`의 **로컬 스키마 시뮬레이션**만 사용하고 현재 미확인 정책에 따라 읽기 전에 정리합니다. 실제 수집 성공으로 사용하지 않습니다.

소스 저장 검사에는 원래 lease 영속화/재시도, 만료된 같은 곡 목록의 검토 유지, JSON으로 외부 정보/기한을 복원하지 못하는 3개를 추가했습니다. 전체 회귀와 브라우저 결과는 PLAN.md에 기록합니다. 운영 DB/계정·사이트 정책은 변경하지 않았고 외부 요청도 없습니다.
