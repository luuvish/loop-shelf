# 소스 앨범 저장 확인 화면

2026-10-25. 검색 결과의 앨범 상세에서 개인 제목·메모·즐겨찾기를 확인한 뒤 [저장 API](SOURCE_SAVE_API.md)를 호출합니다. **제품의 KHInsider·Zophar 수집/보관은 policy_disabled이며 live 저장도 비활성입니다.** 성공 화면은 명시적인 합성 자료와 임시 서버의 실제 인증·저장 API로 검증합니다.

## 선택과 저장

1. 상세의 `save` 상태·확인 기한·보관 기한을 표시합니다. 정상 fresh 상세와 유효한 저장 안내일 때만 **내 선반에 저장**을 제공합니다. 누락/잘못된 안내, stale·부분 실패·미지원 종류는 저장할 수 없으며 유효한 상세 자체는 계속 읽을 수 있습니다.
2. 먼저 내 계정의 같은 원본 저장 상태를 조회합니다. 이미 있으면 원래 개인 내용을 보여 주고 덮어쓰지 않습니다. 없다면 개인 필드를 입력합니다. 제목을 비워 두면 `titleOverride: null`이며 외부 제목을 개인 필드에 복사하지 않습니다.
3. **저장 내용 확인**으로 앨범·출처·계정과 개인 내용을 확인합니다. **확인하고 저장**을 눌러야 쓰기를 시작합니다. 수록곡 개별 저장·음원 파일 보관은 하지 않습니다.
4. 요청에는 sourceId/externalKey, 확인한 fingerprint, 개인 필드만 보냅니다. fingerprint는 화면에 노출하거나 음악 ID로 사용하지 않습니다. 저장 시점의 재검사와 원자적 반영은 서버가 수행합니다.
5. 성공 응답은 선택한 원본·주소·자료 종류·개인 필드 형식을 검증합니다. 200 중복은 기존 내용을 유지하며, `review_required`는 수록곡 변경의 검토 대기로 안내합니다. 결과에는 개인 제목/메모/즐겨찾기만 남기고 **저장한 카탈로그 확인**으로 관리 화면에 이동합니다.

## 불확실한 결과와 재확인

요청 유실·취소·시간 제한은 이미 저장되었을 수 있는 상태입니다. 자동 재전송하지 않고 입력 내용을 보존한 채 **선반과 상세 다시 확인**을 제공합니다. 같은 원본의 개인 저장과 최신 상세를 다시 조회하며, 미저장이 확인되면 새 관찰/개인 내용을 명시적으로 확인해야 합니다. 재확인 취소는 함께 진행하던 상세 조회도 중단합니다. 뒤늦은 응답은 취소한 작업을 되살리지 않습니다. 다른 저장이 먼저 성공하면 기존 개인 필드가 우선합니다.

`GET /api/library/catalog/source-save`는 관리 중인 정확한 원본 SourceEntity→Album UUID와 현재 계정의 저장 행만 조회합니다. 제목/URL 유사성, 추가 출처 연결, 다른 UUID의 미연결 참조를 매칭하지 않습니다. `item: null`은 선반 전체에 같은 음악이 없다는 뜻이 아닙니다. 미연결 자료와 추가 연결은 관리 화면에서 별도로 확인해야 하며 자동 재연결하지 않습니다.

정책 변경·제거·기한 만료는 이전 상세/검색 자료를 지웁니다. 확인 기한은 서버의 `validUntil - completedAt`에서 전체 요청/현재 쿠키 검사 시간을 뺀 뒤 단조 시계로 관리합니다. 확인 기한이 지나면 제출을 막고 진행 중인 저장은 취소한 뒤 결과 재확인을 요구합니다. 429 대기는 검색/상세와 공유하고 종료 뒤에도 직접 재시도해야 합니다.

## 세션·초안·오프라인

성공 응답의 사용자/세션 헤더를 비교하고 현재 쿠키의 실제 세션도 다시 확인합니다. 실패 응답도 현재 세션을 검사한 뒤 보여 줍니다. 다른 창에서 로그인했더라도 기존 쿠키 세션이 서버에서 자동 폐기되었다고 가정하지 않습니다. 현재 세션 확인이 실패하면 성공을 확정하지 않으며 오래된 요청의 결과를 새 계정에 노출하지 않습니다. 클라이언트 요청/세션 검사 합계 예산은 기존 15초입니다.

초안은 React 메모리에만 보관합니다. 오프라인에서는 요청을 취소하고 원본 상세/검색 자료와 확인값을 제거합니다. 개인 초안이 있으면 숨겨진 상세 창을 유지하며, 온라인 복귀 때 실제 세션이 같아야 다시 보여 줍니다. 자동 조회·저장은 하지 않습니다. 닫기·화면 이동·문서 숨김/창 복귀·로그아웃·401·계정 전환 시 창과 초안을 제거합니다. localStorage/sessionStorage·Service Worker·오프라인 쓰기 큐는 사용하지 않습니다.

- `tests/source-save-api.test.ts`: 기존 저장 API 검사에 정확한 개인 조회의 실제 세션·소유권·잘못된 입력·제거 보존·미연결 참조 비매칭 3개를 추가합니다.
- `tests/browser/source-save.spec.ts`: 데스크톱 1440×1000·모바일 360×800의 명시적 확인, 이중 클릭·중복 경합, 변경 관찰·유실/취소·기한·요청 제한·오프라인, 현재 쿠키 확인 실패·다른 계정 전환과 잘못된 결과를 검증합니다. 캡처는 `test-results/`에 생성합니다.

전용 `tests/browser/source-save-fixture.ts`는 4197/4198의 임시 E2E 서버에만 연결합니다. 검색 결과는 합성 응답이며 상세/저장에는 합성 서비스와 실제 HTTP·SQLite·쿠키 인증을 사용합니다. 제품의 요청 제한과 인증은 유지하며 충분한 요청으로 제한에 도달하면 화면의 실제 대기 뒤 명시적으로 재시도합니다. 외부 요청을 차단하고 운영 DB/계정은 사용하지 않습니다. 제품 HTTP/env로 자료 종류나 정책을 바꾸는 통로는 없습니다. 실제 휴대전화·Safari·실사이트 연동·오디오/CORS 검증은 포함하지 않습니다.

최종 검증: strict 타입·프로덕션 빌드·Node **391개**, 전체 Playwright **17개** 통과. 재확인 취소의 상세 요청 전달 후 관련 상세/저장 **4개**, 마지막 재확인 상태 표시 보완 후 `check` **391개**와 저장 화면 **2개**도 통과했습니다. 데스크톱·모바일의 확인/성공/충돌 캡처와 가로 넘침을 확인했습니다. 스키마/패키지·운영 자료·실사이트 정책은 변경하지 않았습니다.
