# LoopShelf 설치·오프라인·업데이트

구현·검증일: **2026-10-22**. 기본 PWA는 앱 설치 정보와 정적 앱 셸, 연결 안내를 제공합니다. 북마크 조회·변경·JSON 이식은 서버 연결이 필요합니다. 음악 재생·개인 라이브러리 오프라인 열람·백그라운드 저장은 포함하지 않습니다.

## 설치와 이용

`npm run build` 후 `npm start`로 실행합니다. 개발 서버는 Service Worker를 등록하지 않습니다. 로그인 화면이나 **내 계정 → 앱 설치·업데이트**에서 안내를 볼 수 있습니다. 브라우저가 실제 설치 이벤트를 제공하면 **LoopShelf 설치** 버튼을 표시하고, 그 외에는 브라우저의 앱 설치/홈 화면 추가 메뉴를 이용합니다. 설치 메뉴 지원은 브라우저와 플랫폼마다 다릅니다. 설치 후에도 같은 서버 계정으로 로그인합니다.

Service Worker에는 HTTPS 또는 신뢰할 수 있는 loopback 주소가 필요합니다. 로컬 검증은 `http://127.0.0.1:3000`에서 가능하지만 LAN의 일반 HTTP 주소로 확대 적용하지 않습니다. 현재 앱은 origin 루트(`/`) 배포를 전제로 하며 하위 경로 배포는 지원하지 않습니다. [MDN 설치 요구사항](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

온라인에서 정적 앱 셸을 준비한 뒤 연결이 끊기면 **연결이 필요해요** 화면이 표시됩니다. 기존 창의 편집 내용은 메모리에 유지되며 대화상자를 잠시 닫아 개인 화면을 숨깁니다. 온라인 복귀 후 실제 세션을 확인하고, 같은 세션일 때만 기존 화면과 초안을 다시 보여줍니다. 세션이 만료되거나 계정이 바뀌면 초안을 제거합니다. 창을 닫거나 새로고침하면 저장하지 않은 초안은 사라집니다. 최초 방문부터 오프라인이거나 브라우저가 앱 캐시를 제거한 경우에는 오프라인 화면도 제공할 수 없습니다.

오프라인 요청은 저장 성공으로 표시하거나 나중에 자동 전송하지 않습니다. 연결이 끊기기 직전에 보낸 요청의 결과가 불명확할 때는 기존 버전 충돌·재조회·JSON 재검사 규칙을 따릅니다. 사용자가 다운로드한 JSON 파일은 별도의 개인 백업이며 앱 캐시에 보관하지 않습니다.

## 업데이트

앱을 열거나 온라인으로 돌아올 때 업데이트를 확인합니다. 포커스/온라인 이벤트에 따른 추가 확인은 최소 60초 간격이며 **업데이트 확인** 버튼으로 직접 확인할 수도 있습니다.

새 버전의 모든 정적 파일을 준비하면 안내를 표시합니다. 입력을 저장한 뒤 **같은 origin의 LoopShelf 탭과 설치된 앱 창을 모두 닫고 다시 열면** 적용됩니다. 새로고침만으로는 기존 worker의 대기가 끝나지 않을 수 있습니다. `skipWaiting`이나 강제 새로고침을 사용하지 않습니다. 불완전한 배포나 파일 검증 실패는 새 worker 설치를 중단하며 이전에 검증된 앱 셸을 유지합니다. [MDN Service Worker 수명 주기](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)

배포는 빌드 전체를 준비한 뒤 교체합니다. 실행 중인 `dist/`를 비우면서 빌드하지 않습니다. 앱 셸과 API의 이전 버전 호환성을 유지하고, 기존 창이 모두 종료되기 전에는 이전 해시 자산도 사용할 수 있게 운영해야 합니다. 실제 TLS 프록시·원격 호스팅 배포는 아직 검증하지 않았습니다.

## 캐시 계약

| 대상 | 동작 |
| --- | --- |
| 정적 `index.html`, Vite JS/CSS, manifest, favicon, PNG 아이콘 | 빌드 시 명시한 목록만 설치 단계에서 캐시 |
| `/`, `/index.html` 탐색 | 네트워크 우선, 4초 timeout·통신 실패·5xx 시 검증된 정적 HTML로 대체. 네트워크 HTML은 저장하지 않음 |
| 허용 목록의 정적 자산 | 해당 버전 캐시 우선, 없으면 네트워크. 런타임 캐시 쓰기 없음 |
| `/api/*`, 로그인/세션, 북마크, JSON export/import | Service Worker 개입·캐시 없음. HTTP `no-store` 유지 |
| 외부 사이트/오디오, 임의 파일, query 포함 URL, Range, GET 이외 요청 | Service Worker 개입·캐시·재전송 없음 |

`scripts/build-pwa.ts`가 공개 빌드 자산의 SHA-256 목록과 worker 소스로 버전 ID를 계산해 `dist/sw.js`를 생성합니다. worker는 쿠키 없이 같은 origin의 목록 파일만 요청하며 redirect를 거절하고 각 요청에 15초 제한을 적용합니다. 모든 파일의 내용 해시가 일치한 뒤 저장합니다. Cache Storage 이름은 `loopshelf-shell-v1-<version>`입니다. 활성화 시 이 접두사의 이전 버전만 삭제하며 다른 앱 캐시는 지우지 않습니다. 개인 데이터가 들어가는 캐시 자체를 만들지 않으므로 로그아웃·계정 전환 후에도 공개 셸만 남습니다.

`worker/service-worker.ts`는 WebWorker 전용 strict 타입 검사를 받습니다. 서버는 worker·manifest에 동일 origin CSP와 `no-store`를 적용합니다. `web/public/icons/`의 PNG는 기존 선반 로고의 기하 도형으로 생성했으며 `npm run icons`로 재생성합니다. 192/512px 일반 아이콘, 512px maskable 아이콘, 180px Apple touch 아이콘이 있습니다.

개발 모드에서는 `/sw.js`를 404로 반환합니다. 동일 origin에서 이전 빌드를 이용했다면 개발 클라이언트가 정확히 `/sw.js`에 해당하는 root 등록과 LoopShelf 셸 캐시만 제거합니다. 운영과 개발은 별도 origin을 사용하는 편이 안정적입니다.

## 검증과 남은 범위

`npm run check`는 서버·브라우저·worker strict 타입 검사, 빌드, **134개 Node 테스트**를 실행합니다. worker 검증에는 공개 파일만 포함하는 결정적 빌드, 내용 불일치 거절, 비공개/외부/Range 요청 제외, 오프라인 fallback, 이전 셸 정리가 포함됩니다.

`npm run test:e2e`는 **11개 Playwright 시나리오**입니다. 데스크톱/모바일 북마크·JSON 이식 2개, 카탈로그 관리 2개, 개발 서버 1개, PWA 설치·오프라인·업데이트 5개와 DB 복구 1개입니다. PWA 검증 내용은 다음과 같습니다.

- 데스크톱 1440×1000과 모바일 360×800에서 실제 로그인·북마크·내보내기 후 캐시 목록 검사, 초안이 열린 상태의 오프라인 전환, 같은 세션 복귀, 오프라인 중 실제 계정 변경 후 초안 제거, 로그아웃, 오프라인 새로고침과 재접속.
- 두 화면에서 손상된 릴리스 설치 실패와 기존 캐시 유지, 정상 업데이트의 대기, 기존 모든 창 종료 후 활성화, 새 버전 오프라인 실행.
- 전체 Chromium의 임시 프로필에서 실제 manifest의 설치 가능 오류 없음, CDP `PWA.install`, 앱 창 모드 설정, `PWA.launch` 후 `display-mode: standalone`, `PWA.uninstall` 확인. 테스트 종료 시 앱과 임시 프로필 제거. [Chromium PWA 프로토콜](https://chromedevtools.github.io/devtools-protocol/tot/PWA/)

- DB 복구 시나리오에서는 실제 서버가 중단된 동안 새 PWA 탭에 공개 셸만 표시하고, 새 DB로 서버가 돌아온 뒤 이전 세션·초안을 제거하고 재로그인·검색·수정하는 흐름을 확인했습니다. 복구는 같은 origin에서 수행했습니다. [복구 절차](OPERATIONS.md)

검증 브라우저는 Chromium 156입니다. 모바일은 에뮬레이션이며 실제 Android/iOS 설치, Safari/Firefox, 브라우저의 일반 설치 메뉴 조작과 원격 HTTPS 배포는 미검증입니다. 이 결과를 모든 기기에서의 설치 보장으로 간주하지 않습니다. 테스트는 별도 임시 DB와 loopback 서버만 사용하며 외부 음악 사이트를 호출하지 않습니다. 화면 캡처는 Git에서 제외한 `test-results/`에 생성됩니다.
