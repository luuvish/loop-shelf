# 통합 검색 서비스 — 오프라인 계약

2026-10-24. 로컬 카탈로그와 KHInsider·Zophar 검색 Adapter를 조합하는 내부 TypeScript 서비스를 구현했습니다. 후속으로 [인증된 HTTP API](SEARCH_API.md)에 연결했습니다. [React 검색 화면](SEARCH_UI.md)을 연결했습니다. **실제 수집 자료의 카탈로그 적재는 아직 연결하지 않았습니다.** 실제 소스 정책은 변경하지 않았으며 자동 수집/캐시 제공은 비활성입니다.

## 진입점과 자료 경계

- 제품 진입점은 `src/search.ts`의 `getSearchService(db).search(input, signal?)`입니다. DB 연결마다 인스턴스를 재사용하고 제품 Adapter와 정책을 고정합니다. 환경 변수나 요청으로 허용 정책·전송 함수·sampleKind를 교체하지 않습니다.
- `src/search/service.ts`의 `createSearchService`는 합성 응답·가짜 시계·지연을 주입하는 신뢰된 내부 테스트 경계입니다. 실제 HTTP 요청에서 의존성을 만들지 않습니다.
- 제품 모드는 `live-capture`입니다. 현재 로컬 카탈로그의 관찰은 합성 전용이므로 로컬 부분은 `sample_kind_unavailable`을 반환합니다. 이를 정상 0건으로 표시하지 않으며 합성 자료를 섞지 않습니다. 두 제품 Adapter는 각각 `policy_disabled`를 반환합니다.
- 오프라인 검증 모드는 `synthetic`이며 로컬·Adapter 결과 모두 이 표식을 유지합니다. 다른 sampleKind·소스·검색문·상세 페이지를 돌려준 Adapter 응답은 `invalid_response`입니다.
- 개인 북마크·메모·제목 override·즐겨찾기·저장 표시·미연결 개인 항목은 검색 대상이 아닙니다. userId 입력이나 인증 우회가 없고 개인 테이블을 조회하지 않습니다. 기존 개인 검색은 세션으로 보호되는 별도 API를 계속 사용합니다.

## 요청

```ts
{ q: "星の記憶", sources: ["khinsider", "zophar"], limit: 12, offset: 0 }
```

`q`는 공백만 있는 값을 제외한 최대 200자 문자열이며 제어 문자·고립 surrogate를 거절합니다. 앞뒤 공백만 제거하여 Adapter에 전달하고 대소문자·전각 문자·내부 연속 공백은 원격 요청 키에서 보존합니다. 로컬 검색은 기존 NFKC·소문자·공백 정규화 후 리터럴 부분 검색입니다. 한일문 1–2자, `%`, `_`, 따옴표는 검색 문법으로 해석하지 않습니다. 빈 문자열 목록 탐색은 기존 카탈로그 탐색 API의 역할입니다.

`sources`는 명시적으로 요청할 외부 소스이며 기본값은 빈 배열입니다. 중복·알 수 없는 소스·정의되지 않은 속성을 거절합니다. 로컬 카탈로그는 두 출처를 대상으로 조회하고 이 배열로 필터하지 않습니다. `limit`(1–100, 기본 12)과 `offset`(0–100,000, 기본 0)은 로컬 페이지에만 적용합니다. 원격 페이지를 임의로 잘라 로컬 offset을 적용하거나 추가 페이지·상세를 자동으로 요청하지 않습니다.

## 결과와 정체성

전체 요청 거절은 `{ ok: false, code: "invalid_input" | "cancelled" | "queue_full" }`입니다. 실행한 검색은 `ok: true` 봉투 안에 다음을 반환하며, `ok: true`만으로 검색 성공을 판단하지 않습니다.

| 필드 | 의미 |
| --- | --- |
| `query`, `sampleKind` | 검증한 검색문과 전체 응답의 자료 종류 |
| `status` | `complete`, `partial`, `failed`. 실제 결과 개수가 아니라 각 부분의 성공/실패 상태 |
| `termination` | `settled` 또는 전체/소스 예산에 의해 끝난 `deadline` |
| `completedAt`, `elapsedMs` | 응답 완료 시각·경과 시간. 외부 취득 시각을 대체하지 않음 |
| `local` | 성공 시 앨범 목록·`nextOffset`, 실패 시 코드. 로컬 최신 조회 값도 `freshness: not-revalidated`로 표시 |
| `sources` | 고정 KHInsider→Zophar 순서의 선택한 소스만 포함. 각 소스의 정책 판단/버전과 독립 성공·실패 결과 |

로컬 결과는 Album/SourceEntity UUID, 현재 채택 제목과 그 제목의 관찰 provenance를 포함합니다. 더 최근의 검색 표시명이 상세 제목의 근거를 대체하지 않습니다. 제거/차단/not_found·비활성 자료는 제외합니다. 앨범 우선 조회 SQL은 기존 탐색과 공유하고, 제목→소스→원본 키→UUID 정렬과 실행 계획을 유지합니다. 스키마·FTS·인덱스를 추가하지 않았습니다.

원격 결과는 기존 `SearchPage`와 provenance·warnings, `delivery.from: transport | cache`, `freshness`, `freshUntil`, `expiresAt`, 선택적 `refreshFailure`를 보존합니다. 원격 `reportedCount`·`coverage`·미검증 `nextPageUrl`을 로컬 페이지 정보와 분리합니다. `reported-count-matches`도 사이트 전체 카탈로그의 완전성을 보장하지 않습니다.

각 소스 내 중복 원본 키는 기존 DTO 검증에서 거절합니다. 서로 다른 소스의 같은 제목을 병합하거나 원격 항목에 새 공용 UUID를 부여하지 않습니다. 같은 원본이 로컬과 원격 부분에 모두 있으면 각 부분의 취득 근거와 함께 유지합니다. 전체 결과를 합한 “고유 음악 수”를 계산하지 않습니다. 이 서비스는 카탈로그·개인 저장 행을 생성하지 않습니다.

정상 0건도 성공입니다. 반면 `parse_changed`, `blocked`, `rate_limited`, `timeout` 등 실패에는 빈 `albums`를 만들어 넣지 않습니다. 모든 부분이 성공하고 stale·갱신 실패·부분 페이지가 없으면 `complete`입니다. 하나라도 성공한 부분이 있으면서 실패/불완전 자료가 있으면 `partial`, 성공한 부분이 하나도 없으면 `failed`입니다. 따라서 로컬 정상 0건과 원격 실패가 함께 있으면 `partial`이며 “전체 0건”이 아닙니다.

## 시간 예산·취소·마지막 검사

서비스는 연결별 동시 검색 16개까지만 받고 별도 검색 큐를 만들지 않습니다. 선택한 두 Adapter를 병렬로 실행합니다. 기존 Adapter의 캐시 우선·요청 병합·소스별 전송 제한을 그대로 사용합니다.

1. 전체 비동기 대기 예산은 시작부터 **12초**입니다. 소스 대기는 **11초**에 종료하고 남은 1초를 DB 큐 대기·현재 로컬 조회·마지막 노출 검사에 남깁니다. 두 소스 시간을 차례로 더하지 않습니다.
2. 먼저 끝난 소스 응답을 보유한 동안 다른 소스가 지연될 수 있으므로, 종료 전에 `withDatabase` 안에서 정책 판단/버전·캐시 만료·제거 결정을 다시 확인합니다. 그 시점의 로컬 카탈로그도 조회합니다. 네트워크를 기다리는 동안 DB 경계를 점유하지 않습니다.
3. 표시가 금지되면 해당 실패를 반환하고, 정책 버전/판단이 바뀌면 `policy_changed`로 버립니다. 캐시는 캐시·표시 허가를, 새 전송 결과는 수집·표시 허가를 요구합니다. 취득이 금지되어도 별도 캐시·표시 허가가 유지되는 기존 캐시는 계약상 제공할 수 있습니다.
4. 기다리는 동안 fresh 경계를 넘으면 stale로 재표시합니다. 만료를 넘으면 `result_expired`, 제거된 원본이 하나라도 포함되면 해당 소스 전체를 `content_removed`로 반환합니다. 취득 시각/수명을 연장하거나 제거 항목을 빼고 정상 0건으로 바꾸지 않습니다.
5. DB의 마지막 검사를 시간 내에 할 수 없으면 확인하지 못한 보유 메타데이터를 반환하지 않습니다. 로컬과 해당 성공 후보는 `timeout`이 되고 이미 확정된 소스 실패는 보존합니다. 로컬 조회만 실패한 경우에는 확인 가능한 소스 결과를 유지합니다.
6. 호출자 취소는 전체 결과를 폐기하고 해당 검색의 Adapter 구독만 해제합니다. 다른 호출자가 공유 중인 전송은 유지하며 마지막 구독자 취소 뒤 늦은 응답은 캐시에 저장하지 않습니다. 취소를 무시하는 의존성을 기다리지 않으며, 중단된 DB 큐 작업도 잠금 획득 후 읽기 전에 종료합니다.

정책·제거 검사는 응답 생성 시점의 판단이며 이미 전달된 응답을 소급 회수하지 않습니다. 전역 결과 캐시나 자동 재시도는 추가하지 않았습니다. 호출자는 필요하면 실패한 소스를 명시적으로 다시 선택할 수 있으며 재시도 UI는 후속 작업입니다. 동기 SQLite/JavaScript 실행 자체를 선점할 수는 없으므로 12초는 비동기 대기 제한이며, 실행 후에도 경과 시간을 검사합니다. 이벤트 루프 정지나 다중 프로세스 동시 변경까지 보장하는 실시간 제한은 아닙니다.

## 검증과 남은 일

`tests/search-service.test.ts`의 **31개 테스트**에서 다음을 확인했습니다.

- 현재 로컬 제목·관찰 근거·UUID, 출처 구분, 페이지/한일문/리터럴 검색, 비가용·제거 제외, 개인 필드 비조회와 앨범 우선 실행 계획.
- 명시적 소스 선택, 정상 0건·부분 페이지·stale/갱신 실패·429 안내·파서 실패·예외 격리, 잘못된 sampleKind·원본·요청 응답 거절.
- 가짜 시계의 11초 소스 중단/12초 DB 대기 중단, 부분 결과, 취소/동시 상한/늦은 응답, 종료 전 정책 변경·만료·제거 재검사.
- 실제 메타데이터 Adapter와 임시 SQLite를 이용한 공유 구독자의 독립 취소·캐시 저장/재사용, 마지막 구독자 취소 후 저장 금지.
- 제품 서비스의 합성 자료 비노출과 `policy_disabled`, DNS 호출·캐시 쓰기 없음.

`npm run check`: strict 타입 검사·프로덕션 빌드·총 **268개 Node 테스트** 통과. 실제 사이트·운영 DB를 사용하지 않았습니다. 기존 카탈로그 실행 계획/권한/백업 등 회귀 검증도 통과했습니다. 화면 변경이 없어 브라우저 E2E는 이번 단위에서 재실행하지 않았습니다.

인증된 HTTP API의 세션 검증·요청 종료 취소·응답 캐시 금지 연결을 완료했습니다. 비동기 인증 대기 뒤의 `recheck(input, result)`는 호출자가 소유한 DB 경계 안에서 현재 로컬 값·정책·만료·제거·요청 문맥을 다시 검사하며 새 수집이나 적재는 하지 않습니다. React 표시/재시도, 허용된 live 카탈로그 적재·검색, 별칭·곡 검색, 사이트별 robots/path/quota와 보관 근거, 배포 부하 검증은 남아 있습니다. 이 문서는 실제 통합 검색이나 MVP 전체의 완료 근거가 아닙니다.
