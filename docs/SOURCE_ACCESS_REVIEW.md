# 소스 접근 검토 계약

2026-10-25. 검색/상세 수집 허가, robots 경로 검토, 공식 요청 한도를 별도 근거로 검사하는 내부 계약을 추가했습니다. **실제 사이트 허가를 등록하거나 수집을 활성화하지 않았습니다.** 제품의 KHInsider·Zophar 정책은 unknown, KHInsider 상세 기술 상태는 blocked이며 제품 검토 목록은 비어 있습니다.

## 구현 범위

`src/sources/access-review.ts`는 검토 자료의 엄격한 형식 검사와 순수 판정을 담당합니다. 네트워크·DB·파일 읽기나 원문 실행은 없습니다. `review-policy.ts`의 고정 제품 목록만 전송 gate와 연결하며 HTTP/env/DB/CLI로 검토를 주입하거나 활성화할 수 없습니다. 테스트 자료는 `tests/source-access-review.test.ts`의 synthetic 객체이며 운영자 허가나 실사이트 관찰이 아닙니다.

`parseAccessReview`는 잘못된 필드·알 수 없는 버전/옵션·중복 주소·일관되지 않은 시각을 거절합니다. 형식 검사를 통과한 것은 기록된 근거가 진짜이거나 운영자의 판단이 옳다는 증명이 아닙니다. 해시는 증거의 식별용이며 원문을 가져와 대조하거나 전자 서명을 검증하지 않습니다. 근거의 진위·범위·권한은 별도로 검토해야 합니다.

## 검토 항목

| 항목 | 필요한 내용과 검사 |
| --- | --- |
| 정체성과 버전 | `exact-target-review-v1`, sourceId, synthetic/live-capture, 현재 assessmentRevision. 다른 소스·합성 자료·이전 정책으로 대체 불가 |
| 검토 기간 | ISO UTC `reviewedAt <= now < expiresAt`. 근거의 observedAt은 검토 시각보다 늦을 수 없음 |
| 수집 허가 | search/album 각각 allowed/denied/unknown, 운영자의 명시적 허가 또는 공개 허가 문서, 참조·원문 SHA-256·관찰 시각·검토한 범위 |
| 별도 권한 | cache/display/catalog의 독립 판정과 근거. cache/catalog 허용 주장에는 양수 maxRetentionMs 필요. 수집 허가에서 파생하지 않음 |
| robots | 정확한 origin의 `/robots.txt`, 상태·SHA-256·관찰/만료 시각, 고정 User-Agent와 `LoopShelf` product token, 수동 검토 방법 |
| 경로 | 검색/상세 구분, query 포함 정확한 URL, 해당 주소의 robots 판정과 검토 근거. 최대 200개, 중복 금지 |
| 요청 한도 | 공식 quota 문서 또는 운영자 허가, 적용 범위·최소 간격·동시성·기간별 한도·추가 조건·실패/redirect를 포함한 모든 시도의 적용 여부 |

허가 문서·robots 파일·quota는 서로 대체할 수 없습니다. 예를 들어 robots 허용이나 HTTP 200을 수집 허가 evidence에 넣으면 형식부터 거절합니다. 근거를 확인할 수 없다면 unknown으로 유지합니다. 새 자료는 사람이 검토할 소스 변경이며, 이 계약을 채웠다는 이유로 기존 assessment를 자동으로 allowed로 바꾸지 않습니다. 실제 허가가 녹음/이미지 등 권리까지 포괄한다고 추정하지 않습니다.

## robots와 정확한 주소

이 버전은 **robots.txt 자동 취득기·문법 파서·와일드카드 매처가 아닙니다**. 검토자가 robots 원문에서 해당 User-Agent의 적용 그룹, 중복 그룹 결합, Allow/Disallow, 가장 구체적인 규칙, 인코딩·쿼리·특수 문자를 확인한 뒤 정확한 대상 주소별 결론을 기록합니다. 그 결론과 원문 해시·기한을 함께 묶습니다. 판단이 불명확한 주소는 unknown입니다. 표준상 그룹/규칙 해석은 [RFC 9309 §2.2](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.2)를 따르는 검토 항목이며, 코드가 그 해석을 수행했다는 뜻은 아닙니다.

기존 고정 요청/동일 리소스 redirect 검사를 먼저 통과해야 합니다. 검토 주소는 URL 직렬화와 일치해야 하며 다른 origin, 추가 query, 사용자 정보, fragment, 경로 탈출을 등록할 수 없습니다. 같은 검색어라도 `%73`/`s`, query 순서, 상세 뒤 `/` 등의 표현이 달라지면 각각의 정확한 주소가 필요합니다. 검토한 prefix를 전체 경로에 확대하거나 요청 URL을 디코딩해 robots 결론을 재사용하지 않습니다. 사용자의 검색어를 수집해 검토 목록에 자동 추가하지 않으며 검토 자료에 개인 검색 내용을 기록하지 않습니다.

robots 관찰은 200 응답만 수동 검토 대상으로 인정하고, 만료는 관찰 이후 최대 24시간으로 제한합니다. 더 짧은 사이트/HTTP 기한은 검토자가 적용해야 합니다. 접근 실패·403/404·redirect·429·5xx·상태 미확인은 전부 거절합니다. RFC는 일부 4xx 상황에서 접근을 허용할 수 있지만 이 앱은 그것을 자동 허용으로 해석하지 않으며, unreachable 시 과거 자료의 수명을 연장하지도 않습니다. [RFC 9309 §2.3–2.4](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3)

따라서 임의 검색어·앨범 전체를 활성화하는 검토 계약은 아직 아닙니다. 자동 robots 해석을 추가하려면 버전을 올리고 별도 표본/규칙 검증과 취득 정책을 마련해야 합니다. robots의 접근 지침과 콘텐츠 사용 허가는 계속 독립적입니다.

## 지킬 수 있는 quota만 허용

현재 [0017 조정기](SOURCE_COORDINATION.md)는 같은 호스트의 같은 로컬 DB를 쓰는 설치에서 source origin별 동시 1개, 시도 종료 후 최소 3초를 지킵니다. 이보다 느슨한 공식 제한은 현재의 더 엄격한 실행 값으로 충족할 수 있지만, 더 짧게 기다리거나 더 많이 실행하도록 조정하지 않습니다. 실패·redirect도 포함해 이 설치의 모든 요청에 적용된다는 검토가 필요합니다.

다음은 `quota_unsupported`로 거절합니다.

- 3초보다 긴 최소 간격이나 미확인 간격/동시성.
- 분당·일일 등 기간별 요청 수 제한. 현재 간격만으로 충분하다고 추정하지 않음.
- 여러 소스의 공통 그룹, 여러 설치/DB/호스트의 공통 제한.
- 실패/redirect의 적용 여부 미확인, 검토하지 않았거나 별도 집행이 필요한 추가 조건.

공식 근거 없이 자체 기본값을 입력해 활성화해서는 안 됩니다. 같은 DB를 거치지 않는 수집기나 운영 트래픽이 있는지도 실제 활성화 전에 확인해야 합니다. 시계/재시작/복원/429·불확실한 running의 운영 조건은 기존 조정 계약을 유지합니다. 이 검토기는 배포 조건을 자동 증명하지 않습니다.

## 대기 중 변경과 다른 계층

제품 전송은 기존 productAccess와 새 검토 gate를 모두 통과해야 합니다. 최초 검사 뒤 큐/간격·DNS·redirect·본문·DB 완료/예약 해제 후에도 현재 검토를 다시 읽습니다. 최초의 review revision을 요청에 묶어, 다른 유효한 allowed 검토로 바뀐 경우에도 진행 중 결과를 성공으로 반환하지 않습니다. 외부 응답은 `policy_disabled`이며 내부의 상세 reason/근거/검색어를 노출하지 않습니다. 허가 철회를 확인하기 위해 요청을 자동 재시도하지 않습니다.

revision에는 검토 버전·근거·정확한 주소·기한·권한·quota와 현재 source assessment가 반영됩니다. Adapter의 policy revision도 제품 검토 목록과 assessment를 포함하므로 이전 검토 캐시를 새 정책으로 재사용하지 않습니다. 이 변경으로 이전 revision의 캐시는 표시되지 않지만, 전수 삭제 기능을 추가한 것은 아닙니다.

`inspectReviewedPermission`은 cache/display/catalog의 **진단용 검토 주장**과 최대 보관 기간만 반환합니다. 이 결과를 실제 캐시·공용 저장 활성화로 자동 연결하지 않았습니다. 제품 cache/display는 기존 unknown, catalog persistence와 live guard도 그대로입니다. 검토 기간/보관 한도를 실제 캐시 수명과 결합하고 만료·철회 시 전수 정리하는 것은 후속 작업입니다. Artwork/directAudio/embed 및 실제 재생은 이 계약의 대상이 아닙니다.

## 검증

신규 오프라인 24개는 형식/시간·근거 종류·출처/자료 종류/정책 버전·경로/쿼리·독립 권한/보관 주장·지원 가능한 quota, 큐/DNS/본문/완료/해제 대기 중 만료·철회·allowed→allowed 교체, 검토하지 않은 redirect와 제품 DNS/예약/캐시 무변경을 검사합니다. 성공 경로의 DNS/응답/시계/coordinator는 합성 대체이며 실제 TLS·브라우저 CORS·실사이트 허가 검증이 아닙니다. 기존 영속 조정 테스트는 별도로 회귀 실행합니다.

최종 strict 타입·빌드·전체 Node **486개**와 데스크톱/모바일 검색·백업 복구 브라우저 **3개**를 통과했습니다. 최초 로컬 포트 실행 제한으로 실패한 기존 HTTP 5개는 허용된 환경에서 전체 재실행해 통과했습니다. 브라우저 이후 주소 추출을 기존 정규화 함수로 통일한 변경은 최종 Node 전체 검사에 포함했으며 UI는 바뀌지 않았습니다. 상세 결과는 PLAN.md에 기록합니다. 스키마·패키지·화면·운영 DB/계정은 변경하지 않았습니다. 표준 문서만 확인했으며 KHInsider/Zophar 요청이나 외부 운영자 연락은 하지 않았습니다.
