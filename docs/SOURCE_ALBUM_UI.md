# 소스 앨범 상세 화면

2026-10-24. 음악 검색의 로컬·소스 결과에서 **상세 보기**를 누르면 [소스 앨범 상세 API](SOURCE_ALBUM.md)를 호출합니다. 제품의 KHInsider·Zophar 자동 수집은 계속 `policy_disabled`이고 KHInsider 상세 파서는 미지원입니다. 성공 화면은 합성 브라우저 응답으로 검증했습니다. 실제 소스 활성화나 카탈로그 적재를 완료한 것은 아닙니다.

## 조회와 표시

- 사용자가 선택한 결과의 `sourceId`와 `externalKey`만 전송합니다. 원문 URL·검색 제목·공용 UUID·자료 종류·사용자를 요청 본문에 넣지 않습니다. 주소와 원본 키가 고정 소스의 정규 앨범 주소에 맞는 결과에서만 상세 버튼을 제공합니다.
- 상세 창을 열 때 한 번 조회합니다. 검색·포인터 이동에 따른 선취득은 없으며, 창을 다시 열거나 **다시 조회 / 상세 새로고침**을 눌러야 새 요청을 보냅니다. 요청 중 이중 제출은 막습니다.
- 상세 페이지의 `album-title`과 검색의 `source-display-label`은 구분합니다. 상세 제목으로 검색 목록이나 개인 제목을 덮어쓰지 않습니다. 플랫폼·출처 분류·연도 원문을 표시하고, 미확인 발매일을 확정하지 않습니다. 추가 정보는 출처의 주장으로 표시합니다.
- 수록곡은 응답의 행 순서를 유지합니다. `snapshotLocator`는 창 안에서 행을 구분하는 React 키이며 영구 트랙 ID가 아닙니다. 반복 표시 번호도 별도 행으로 남기고, 원문 길이와 해석된 길이를 각각 보여줍니다. null 값을 0초로 바꾸지 않습니다.
- 수록곡은 20개씩 표시합니다. 다음/이전은 받은 자료 안에서 이동하며 네트워크 요청을 보내지 않습니다. 페이지 이동 후 수록곡 제목에 초점을 옮깁니다.
- 취득 시각·보관 기한·캐시/이번 취득·이전 자료·갱신 실패·경고를 표시합니다. 실패를 앨범이나 수록곡 0건으로 바꾸지 않습니다. 정책 비활성·차단·미지원·없는 페이지·제거된 자료에는 불필요한 재시도 버튼을 두지 않습니다.
- 검색과 상세는 같은 화면의 소스별 `retryAt`과 HTTP `Retry-After`를 공유합니다. 창을 닫았다 다시 열어도 대기 시간을 유지하고, HTTP 제한은 검색 버튼에도 적용합니다. 대기 종료 후 자동 요청은 없습니다. 서버의 검색/상세/저장 합계 30회/분·동시 16개 한도가 최종 기준입니다.

상세 조회 자체는 공용 Album/Track/SourceEntity나 개인 저장을 만들지 않습니다. 별도 [저장 확인 화면](SOURCE_SAVE_UI.md)에서 명시적으로 확인한 경우에만 저장 API를 호출합니다. 표지·원격 HTML·스크립트·audio·iframe을 로드하지 않으며 텍스트만 렌더링합니다. 원문 링크는 검증된 선택 주소를 사용합니다. 원문 열기는 청취 기록을 생성하지 않습니다.

## 응답·세션·수명

`web/api.ts`의 공통 클라이언트는 쿠키와 필수 세션 조건으로 POST하고 응답 사용자/세션 헤더를 비교한 뒤, 현재 쿠키의 실제 세션을 다시 확인합니다. 전체 클라이언트 대기 15초는 이 재확인을 포함합니다. 현재 세션 확인 실패·401·다른 계정 쿠키·다른 세션 헤더에 대해 보유한 상세를 표시하지 않습니다.

`web/source-album-response.ts`는 선택한 소스 키/주소와 응답 ref·상세·provenance의 일치, 자료 종류, 표시/전달 정책, 시각과 보관 기한, 필수 앨범/트랙 필드를 검사합니다. 빈/중복 행 키·뒤섞인 순서·위험 주소·합성/live 성공 혼합은 거절합니다. **메타데이터가 없는 실패 응답**은 합성 선택에 대한 제품의 live 정책 비활성 응답도 안내할 수 있습니다. 실패를 실제 수집 성공으로 표시하지 않습니다. 클라이언트 검증은 서버 정책 검사나 live 카탈로그 적재 권한을 대신하지 않습니다.

서버의 `expiresAt - completedAt`에서 요청과 세션 확인에 쓴 시간을 보수적으로 뺍니다. 이 시간이 이미 지났으면 결과를 표시하지 않습니다. 표시 중에도 남은 시간이 지나면 상세와 이전 검색 메타데이터를 제거하고 수동 재조회를 안내합니다. 브라우저 벽시계의 시간대/오차로 보관 기한을 늘리지 않습니다. 타이머 상한을 넘는 긴 기한은 더 일찍 지울 수 있으며 자동 갱신하지 않습니다.

`web/SourceAlbum.tsx`는 요청별 AbortController와 순서 번호를 사용합니다. **조회 취소**, 닫기·Escape·화면 이탈, 문서 숨김/창 복귀, 오프라인·로그아웃·세션 전환 시 취소합니다. 취소 뒤 늦게 도착한 성공이나 401은 새 창/계정을 바꾸지 않습니다. 새 조회를 시작할 때 이전 상세를 비우며, 제거/정책 변경/없는 페이지/차단/만료/검증 불일치가 확인되면 부모의 이전 검색 자료도 비웁니다. 검색문과 소스 선택은 유지해 명시적으로 다시 검색할 수 있게 합니다.

개인 저장 초안이 있는 오프라인 상태에서는 상세 창을 숨겨 유지하되 원본 상세/검색 자료와 확인값은 제거합니다. 개인 초안은 온라인 복귀 후 실제 세션 확인을 거쳐 다시 표시하며 수동 재확인이 필요합니다. [저장 초안의 수명](SOURCE_SAVE_UI.md#세션초안오프라인)

상세/검색 결과는 메모리에만 있습니다. 브라우저 저장소·Service Worker·오프라인 큐에 넣지 않습니다. 오프라인 복귀 후 실제 세션을 다시 확인하고 검색이나 상세를 자동 재개하지 않습니다. 모달은 초점 순환, Escape, 닫은 뒤 원래 버튼으로 초점 복귀를 지원하며, 이전 결과가 지워졌다면 검색 제목으로 돌아갑니다.

## 검증

- `tests/source-album-ui.test.ts`의 4개 테스트: 반복 번호·미확인 값 보존, 선택/자료 종류/주소·정책 불일치 거절, 빈/모호한/만료 수록곡 거절, 메타데이터 없는 정책 실패와 성공 구분.
- `tests/browser/source-album.spec.ts`의 데스크톱 1440×1000·모바일 360×800 Chromium 시나리오 2개: 실제 임시 쿠키 세션과 제품 정책 비활성, 합성 상세·21곡 페이지 이동·원문 주장 안전 표시·수동 재시도/요청 제한 공유, 이중 클릭·취소/닫기 뒤 늦은 401/성공, 실패/만료와 검색 자료 제거, 재인증 대기 중 만료, 오프라인 복귀·다른 계정 쿠키·잘못된 응답 세션·401·다른 창 로그아웃을 검증했습니다.
- 두 화면의 상세/수록곡/정책 비활성/제한 캡처와 가로 넘침·키보드 초점 복귀를 확인했습니다. 외부 요청은 차단하고 0건임을 확인했습니다. 개인 브라우저 저장소도 비어 있습니다.

`tests/browser/source-album-fixture.ts`는 응답 검증 전용입니다. 실제 정책을 열거나 합성 자료를 운영 카탈로그에 적재하지 않습니다. 임시 서버는 4195/4196에서 화면 크기별 DB/계정을 분리합니다. 실제 휴대전화·Safari·실사이트 성공·표시/수집 허가·재생/CORS는 이 검증에 포함하지 않습니다.

전체 회귀 결과: strict 타입 검사·프로덕션 빌드·Node 테스트 **305개**, Playwright **15개** 시나리오가 통과했습니다. 마지막 공통 대기 시간 버튼 보완 후 `check` 305개와 검색/상세 데스크톱·모바일 4개 시나리오를 다시 통과했습니다. 운영 DB/계정·스키마·소스 정책은 변경하지 않았습니다.

후속 저장 입력·보관 정책과 원자적 내부 저장 흐름의 오프라인 검증을 [저장 계약](SOURCE_SAVE.md)으로 추가했습니다. 2026-10-25에 보관 모델·인증된 저장 HTTP와 [React 저장 확인 화면](SOURCE_SAVE_UI.md)을 연결했습니다. 합성 저장의 개인 입력·확인·중복/충돌·응답 유실·현재 쿠키 전환을 검증하며 live 저장은 비활성입니다. 소스 허용 근거·robots/path·quota·보관 기간 검토와 허용된 실사이트 검증 이전에는 제품 수집을 활성화하지 않습니다.
