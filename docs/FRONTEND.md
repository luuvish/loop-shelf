# LoopShelf 브라우저 화면과 개발

검증일: **2026-10-25**. 현재 화면은 **계정별 개인 북마크·합성 카탈로그 탐색/저장/관리와 통합 검색/소스 상태·앨범 상세/수록곡·개인 저장 확인**를 위한 React 앱입니다. KHInsider·Zophar의 앨범 URL과 직접 입력한 제목·메모를 저장합니다. 직접 저장한 북마크의 개인 출처 연결·해제와 JSON 내보내기·가져오기를 제공합니다. 기본 PWA 설치·오프라인 안내·업데이트를 제공합니다. 외부 자동 검색, 앨범 수록곡 취득, 재생은 아직 제공하지 않습니다.

## 실행

먼저 [운영 문서](BACKEND.md)의 환경 설정, 마이그레이션, 로컬 계정 생성을 완료합니다. 기본 주소는 `http://127.0.0.1:3000`이며 `localhost`와 섞지 않습니다.

```sh
# 개발: API와 Vite를 하나의 서버에서 실행
npm run dev

# 빌드 후 실행: 위 개발 서버를 종료한 다음 사용
npm run build
npm start
```

개발에서도 같은 origin의 쿠키와 API를 사용하므로 별도 CORS 예외나 인증 우회가 없습니다. Vite는 Fastify middleware로 연결하고 WebSocket도 같은 listener에 연결합니다. Vite의 파일 제공 범위는 `web/`와 필요한 클라이언트 모듈로 제한합니다. 환경 파일·키·DB·`.local`은 제공하지 않습니다. 개발 서버는 로컬 개발용입니다.

`npm start`는 `dist/` 빌드만 제공합니다. 빌드가 없으면 안내 오류로 종료합니다. 개인 API와 인증 응답, 빌드된 앱 응답에는 `no-store`를 적용합니다. 프로덕션에는 CSP, 프레임 차단, referrer 차단을 추가합니다. `/api/*` 오류가 SPA HTML로 바뀌지 않습니다. 서버 환경 변수는 브라우저 번들에 전달하지 않습니다.

## 구현한 흐름

- 이메일/비밀번호 로그인, 세션 확인·재시도, 계정 정보 조회와 로그아웃.
- 내 북마크 목록, 제목·메모 검색, 즐겨찾기 필터, 최근 저장 순 12개 단위 페이지 이동.
- 지원 앨범 URL 북마크 추가, 제목·주소·메모·즐겨찾기 편집, 삭제 전 확인과 취소.
- 중복 주소는 기존 내용을 보존하고 안내. 저장 중 재제출을 막고 연결 실패 시 초안을 유지.
- 편집 충돌은 자동 덮어쓰기하지 않음. 최신 내용 확인 후 최신 값으로 다시 편집하거나, 명시적으로 내 입력을 유지해 재저장. 삭제 충돌도 최신 내용 확인 후 다시 결정.
- 직접 저장한 자료와 원문 새 탭 링크, 소스 이용 안내. 동작하지 않는 재생 버튼과 가상 음원 자료를 표시하지 않음.
- 반응형 레이아웃, 폼 라벨, 대화상자 초점 순환·Escape·초점 복귀, 로딩·빈 목록·검색 0건·통신 오류의 구분.

삭제 후 60초 동안 같은 창의 **삭제한 북마크 → 되돌리기**로 원래 내용을 복구합니다. 같은 URL/ID가 이미 저장됐으면 덮어쓰지 않고 최신 선반을 보여줍니다. 로그아웃·계정 전환·새로고침 시 안내를 제거하며 브라우저 저장소에는 저장하지 않습니다. [기한·재시도·충돌·세션 계약](DELETION_UNDO.md). 카탈로그 탐색·앨범/곡 저장과 기존 저장 관리는 아래 화면에서 제공합니다. 메모 전체는 편집 창에서 확인할 수 있습니다. 계정 생성·비밀번호 재설정은 로컬 운영 CLI를 사용합니다.

## 음악 검색

메뉴의 **음악 검색**에서 앨범 이름과 외부 소스를 선택합니다. 처음에는 소스를 선택하지 않으며 검색 버튼으로만 요청합니다. 현재 실제 소스는 이용 조건 확인 중이고 로컬 live 자료도 준비 중이므로 이 상태를 0건으로 숨기지 않습니다. 출처별 결과·취득 시각·보관/이전 자료·부분 실패와 명시적 재시도, 로컬 페이지 이동을 제공합니다. 실패 뒤 자동 재전송은 없습니다. **상세 보기**로 선택한 소스의 앨범/수록곡을 조회합니다. 상세 제목·원문 주장·캐시/실패·취소/만료와 현재 쿠키를 재확인하며 20곡씩 표시합니다. 검색과 상세는 알려진 요청 제한을 공유합니다. [상세 화면](SOURCE_ALBUM_UI.md) 검색 결과 저장/재생은 후속이며 **직접 북마크**로 기존 수동 입력 창을 열 수 있습니다. [동작·취소·현재 세션 재확인·검증 범위](SEARCH_UI.md)

## 저장한 카탈로그 관리

메뉴의 **저장한 카탈로그**에서 내 계정에 이미 저장된 합성 앨범·트랙을 관리합니다. 제목·메모·추가 출처의 앨범 제목 검색, 앨범/트랙·즐겨찾기 필터, 최근 저장 순 12개 페이지를 제공합니다. 검색 0건·빈 라이브러리·조회 실패를 구분하고 새로고침할 수 있습니다. 운영 앱에 합성 데이터를 자동으로 넣지 않으므로 새 설치에서는 빈 화면이 정상입니다. **카탈로그 둘러보기**에서 제목 검색·출처 필터·페이지 이동으로 앨범을 찾고 앨범/현재 수록곡을 각각 저장합니다. 상세가 없으면 미수집 상태를 표시하고, 변경 목록 검토 중에는 현재 채택된 수록곡을 보여줍니다. **출처 보기 → 추가 출처 선택**에서 다른 앨범을 선택하고 개인 연결을 확인할 수 있습니다. 원래 출처와 내 계정에서 이미 연결한 출처는 제외하며, 충돌/응답 유실 후 최신 후보를 읽고 재선택합니다. [상세 계약](CATALOG_BROWSE.md)

- 카드에 합성 자료/외부 자료 참조, 앨범/트랙, 원래 소스와 현재 수록 순서·누락·제거·보관 종료 상태를 표시합니다. Track 원문 링크는 소속 앨범 페이지임을 명시합니다. 실제 검색 결과나 재생 가능 자료로 안내하지 않습니다.
- **편집**에서 개인 제목·메모·즐겨찾기를 바꿉니다. 개인 제목을 비우면 현재 카탈로그 제목을 사용하며 원본 제목을 개인 내용에 자동 복사하지 않습니다. 누락·제거·보관 종료된 항목도 개인 내용은 편집할 수 있습니다.
- 편집 충돌과 응답 유실 뒤에는 초안을 유지하고 재저장을 막습니다. **최신 내용 확인**으로 서버 값을 비교한 뒤 내 입력 유지 또는 최신 값 적용을 명시적으로 선택합니다. 이미 삭제한 항목은 다시 만들지 않습니다.
- **출처 보기**는 원래 출처와 추가 앨범의 개인 판단을 구분합니다. 해제할 출처를 확인하고 **연결 해제 확인**을 누릅니다. 출처가 제거되어도 해제할 수 있습니다. 실패 뒤 재조회 전에는 추가 해제를 막으며 최신 출처를 확인하면 뒤쪽 목록도 갱신합니다. 해제는 다른 개인 저장이나 공용 카탈로그를 합치거나 지우지 않습니다.
- **삭제**는 개인 제목·메모·즐겨찾기·추가 출처 연결을 지우는 확인 창을 제공합니다. 60초 복구는 지원하지 않으며 미리 내보낸 카탈로그 JSON으로 복원할 수 있음을 안내합니다. 충돌 시 최신 요약으로 다시 결정하며 응답 유실 후 재조회에서 404면 이미 삭제된 상태로 목록을 갱신합니다.

편집과 확인 대화상자는 키보드·Escape·초점 복귀를 지원합니다. 저장 중 이중 제출을 막고 컴포넌트가 사라지면 요청을 취소합니다. 오프라인에서 개인 화면과 대화상자는 숨기고 초안은 현재 창의 메모리에만 유지합니다. 복귀 시 실제 세션을 재검증하며 다른 계정에는 초안을 넘기지 않습니다. [개인 API·정체성·백업 계약](CATALOG_LIBRARY.md)

## 북마크의 개인 출처 연결

1. 연결할 앨범 주소를 각각 북마크로 저장합니다. 대표로 삼을 카드의 **출처 관리**를 엽니다.
2. 내 단독 북마크를 제목·메모로 검색해 선택하고, 보존할 원래 내용과 대표 항목을 확인한 후 연결합니다. 대표 포함 최대 20개이며 다른 그룹의 항목은 먼저 해제해야 합니다.
3. 선반에는 대표 카드 하나가 표시됩니다. 카드의 제목·메모·즐겨찾기 필터는 대표를 기준으로 하고, 검색에는 모든 연결 출처의 제목·메모를 포함합니다. 출처 수 배지를 눌러 각 원래 제목·주소·메모·즐겨찾기를 확인합니다.
4. **연결 해제**는 선택한 출처를 원래 ID와 내용으로 선반에 다시 표시합니다. 같은 창에서 직전 연결·해제를 되돌릴 수 있습니다. 이후 변경이 있으면 다시 확인해야 하며 대화상자를 닫아도 수동 해제는 계속 가능합니다.

연결 과정에서 메모를 합치거나 즐겨찾기를 덮어쓰지 않습니다. 다른 버전·편곡을 같은 음악으로 확정하지 않으며, 공용 카탈로그나 다른 사용자는 바뀌지 않습니다. 멤버의 내용을 개별 편집하려면 먼저 해제해 편집한 뒤 다시 연결할 수 있습니다. 대표 항목 편집은 다른 출처의 내용을 바꾸지 않습니다. 연결된 북마크를 삭제하려고 하면 출처 관리로 안내합니다.

대표와 선택한 북마크 중 하나라도 변경되면 작업을 거절하고 최신 내용을 다시 불러오게 합니다. 통신 실패로 성공 여부를 알 수 없을 때도 재조회 전에는 추가 변경을 막습니다. 재조회는 선택과 직전 되돌리기 상태를 초기화합니다. 오류를 검색 0건이나 연결 성공으로 표시하지 않습니다.

## JSON 데이터 관리

**내 계정 → 데이터 관리**에서 북마크 전체와 카탈로그 개인 자료를 각각 JSON으로 내보내고 복원합니다. 두 종류를 모두 보관하려면 두 파일이 필요합니다. 공용 카탈로그 메타데이터와 인증·음원은 포함하지 않습니다. 카탈로그 검사 결과에는 원본 미연결로 복원할 수를 표시합니다. 파일 선택 → 검사 결과 확인 → 가져오기 순서이며, ID·내용·연결이 같으면 건너뛰고 충돌이 있으면 전체를 중단합니다. 기존 선반을 자동으로 덮어쓰지 않습니다. 원래 ID와 개인 내용·출처 연결은 보존하고 수정 버전은 새로 부여합니다.

파일별 최대 8 MiB, 해당 종류의 개인 항목 5,000개입니다. 북마크는 연결된 멤버도 건수에 포함합니다. 카탈로그의 원본이 없으면 개인 미연결 항목으로 복원하고, 개인 제목이 없을 때 안내 제목을 표시합니다. 개인 편집·검색·즐겨찾기·출처 해제·삭제·재내보내기를 제공하고 추가 출처 선택은 비활성화합니다. [카탈로그 참조·복원 계약](CATALOG_TRANSFER.md) 파일 선택과 검사 결과는 메모리에만 두고 로그아웃/계정 전환 시 제거합니다. 실패한 가져오기는 파일을 다시 검사해야 하므로 응답 유실 뒤 중복 저장을 막습니다. [파일 포맷·충돌·한도·복원 설명](DATA_TRANSFER.md)

## 사용자 상태와 API 경계

`web/api.ts`는 상대 경로 `/api`로 요청하며 쿠키를 사용합니다. `src/shared/bookmarks.ts`와 `catalog-library.ts`의 타입을 공유하지만 서버의 SQLite·인증 코드는 번들에 포함하지 않습니다. 목록 요청은 취소 가능하고 15초 응답 제한을 둡니다. 검색·페이지가 바뀌면 이전 응답이 새 결과를 덮지 않습니다.

오프라인에서는 개인 화면을 숨기고 기존 창의 초안을 유지합니다. 복귀 시 세션을 다시 확인하고 같은 세션일 때만 보여줍니다. 개인 목록과 초안은 React 메모리에만 둡니다. localStorage, sessionStorage, IndexedDB, Service Worker에 저장하지 않습니다. 로그아웃 성공·401·세션 전환 시 목록과 열린 초안을 제거합니다. 로그아웃 요청이 실패하면 성공으로 표시하지 않고 재시도할 수 있게 합니다. BroadcastChannel은 인증 상태 변경 신호만 보내며 개인 내용과 세션 값을 전송하지 않습니다. 다른 창으로 돌아올 때도 세션을 다시 확인합니다.

브라우저는 현재 세션의 ID를 `X-LoopShelf-Session` 사전 조건으로 전송합니다. 서버는 **항상 쿠키를 먼저 인증**하고, 조건이 현재 세션과 다르면 작업 전에 401을 반환합니다. 이 값은 인증 수단이나 사용자 선택 값이 아닙니다. 다른 창에서 계정이 바뀐 순간에도 이전 초안이 새 계정에 저장되지 않게 합니다. 응답의 `X-LoopShelf-User`가 현재 사용자와 달라도 화면을 비웁니다. 실제 데이터 소유자는 계속 서버 세션에서만 결정합니다.
