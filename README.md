# LoopShelf

**게임 음악을 발견하고, 나만의 선반에.**

프로젝트명은 **LoopShelf(루프셸프)**, 저장소 식별명은 **`loop-shelf`**입니다.

원격 저장소: [luuvish/loop-shelf](https://github.com/luuvish/loop-shelf)

여러 게임 음악 아카이브를 검색하고, 게임·앨범·곡을 탐색하며, 외부 서비스의 변화와 독립적으로 개인 라이브러리를 유지하는 웹 애플리케이션을 계획합니다.

## 현재 상태

**2026-10-18: 조사 및 설계 단계. 구현은 시작하지 않았습니다.**

사용자 승인으로 프로젝트 이름을 LoopShelf로 확정했습니다. 현재 개발 작업은 조사와 계획 단계입니다. 애플리케이션 코드, 의존성 설치, 데이터베이스 생성, 배포는 수행하지 않았습니다. 문서의 기술 선택과 범위는 제안된 기준안입니다.

## 제안 방향

1. KHInsider와 Zophar의 연동 가능성을 먼저 검증합니다. 현재 두 사이트의 검색 HTML은 확인했지만, KHInsider 앨범 요청에서 403 차단이 발생했고 자동 수집 허용 범위도 미확인입니다.
2. 음악의 정체성과 외부 페이지·재생 리소스를 분리합니다. 원본 URL이 사라져도 사용자 저장 항목의 내부 ID는 유지합니다.
3. 첫 MVP는 검색, 앨범과 수록곡 탐색, 계정별 저장·즐겨찾기, 직접 URL 북마크, 반응형 UI, 기본 PWA입니다.
4. 허용 범위를 확인한 소스만 자동 수집을 활성화합니다. 차단된 소스는 캐시 상태와 원문 링크를 표시하며, 검색 실패를 결과 없음으로 처리하지 않습니다.
5. 스트리밍·플레이리스트·자동 청취 기록은 다음 단계입니다. 외부 페이지를 열었다는 이유만으로 재생 이력을 만들지 않습니다.

기술 기준안은 React + Vite, TypeScript 서버(Fastify), SQLite + FTS5입니다. 소규모 비공개 셀프호스팅과 단일 서버를 출발점으로 삼되, MVP 완료 조건에 사용자별 데이터 격리를 포함합니다. Decl은 추후 실험 대상으로 두며 첫 MVP의 필수 의존성이 아닙니다.

실행 명령은 구현을 시작한 뒤 실제로 검증한 내용만 추가합니다.
